# 動画オーバーレイ書き出し 設計メモ

GPS ログとラップ解析の結果から、走行動画に重ねる透明な動画素材を書き出す機能の設計。
AviUtl + VSD for GPS（`standard_l3` スキン）の表示を参考にし、DaVinci Resolve で重ねて使う。

## 1. 予備調査で決まったこと（2026-11-14）

- **素材の形式**: 透明度付きの ProRes 4444（`.mov`）。ffmpeg で `prores_ks -profile:v 4444 -pix_fmt yuva444p10le` に書き出したものを Resolve の V2 に置き、背景が透けて重なることを確認済み。透明 PNG も同様に重なる。
- **位置合わせ**: Resolve 側で行う。ツールは「実時間どおりに進む素材」を作るだけで、同期機能は持たない。
- **フレームレート**: 選べるようにする（23.976 / 24 / 29.97 / 30 / 59.94 / 60）。違っていても Resolve が実時間に合わせるが、タイムラインとそろえると動きが滑らか。
- **見た目**: VSD の `standard_l3` に合わせられることを見本で確認。ただし全体を控えめな大きさにする。
- **レイアウト**: スキンのように設定ファイルで調整する（`*.overlay.ini`）。
- 試作: リポジトリ外の `overlay_test\`（`make_alpha_test.py` = 透明動画の試験、`mock_layout.py` + `overlay_layout.ini` = レイアウト見本）。

## 2. 画面構成

```
│ [コース図]                      Session 2  Driver 名前 │
│  ライン・セクター線                                        │
│  現在位置                                [ラップ表] Time 0'41.611 │
│                                                +0'00.210 │
│                                                Best   0'33.655 │
│                                                  8    0'33.831 │
│                                                  9    0'33.655 │
│                                                 10    0'34.533 │
│                                                                 │
│                                       [セクター表]               │
│                         Sector   S1     S2     S3     S4         │
│                                 12.345 10.123  8.456  9.012      │
│ [速度計][G][文字データ]          +0.123 -0.045 +0.210 +0.003     │
│                         Best    12.222 10.168  8.246  9.009      │
│                           8     12.301 10.200  8.300  9.030      │

└───────────────────────────────────────────────┘
```

| 部品 | 既定の位置 | 内容 |
|---|---|---|
| コース図 `[map]` | 左上 | コース定義の中心線（決定済み）、**コントロールライン・セクターライン**、現在位置 |
| セッション情報 `[session]` | 右上（右寄せ） | `Session 2  Driver 名前` の 1 行。ベストはラップ表にあるので出さない |
| ラップ表 `[laptime]` | 右上、セッション情報の下に少し間隔を空ける | 現在のラップタイム、ベストとの差、ベスト、ラップ履歴（今の見本どおり） |
| セクター表 `[sector]` | 右下 | 下記 |
| 速度計 `[speedometer]` / G `[gmeter]` / 文字データ `[info]` | 左下に下揃え | 見本どおり。速度計の目盛りの最高値は「書き出す範囲の GPS 最高速 + `margin`（既定 5 km/h）」を大目盛りの刻み `step`（既定 10 km/h）で切り上げた値（例: 最高 93 km/h → 98 → 100）。`max` を指定すれば固定値にもできる。書き出し中は一定（セッションごとに変えない） |
| グラフ `[graph]` | 右下（既定は非表示） | 速度・G の時系列。セクター表と重なるので、使うときは位置を変える |

### ラップ表とセクター表の中身

「ベスト」は**セッション内のベスト**を基準にする（全セッション通しにするかは設定 `best = session / all`、既定 session）。

**ラップ表（右上）**
1. `Time` 現在の周回の経過時間（コントロールライン通過で 0 から）
2. 差分: ベストラップとの差を**リアルタイムに**更新する（＋は遅い・赤、−は速い・青）。今の周回の経過時間と、ベストラップが**コース上の同じ位置**に来た時刻との差（「同じ位置」はコース中心線に沿った距離の割合で比べる。比較再生の `ReplayLap.TimeAtProgress` と同じ考え方）。コントロールライン通過時はその周回の確定した差を表示し、次の周回が少し進むまで保持する（保持秒数は ini）
3. `Best` セッション内のベストラップ
4. 履歴: 直近の周回（`laps` 行）。ベストの周回は `best` 色

**セクター表（右下）**（ラップ表と同じ構成で、列がセクター）
1. 見出し行: `Sector  S1  S2 ...`（セクター名は `CourseDefinition` の数から）
2. 現在の周回のセクタータイム: 通過済みの区間は確定値、走行中の区間は経過時間を表示し（区間に入った時点から刻々と進む。決定済み）、未走行は空欄
3. 差分行: 区間ごとのセッション内ベストとの差。通過済みの区間は確定した差、**走行中の区間はリアルタイムに更新**（区間内の経過時間と、その区間のベストを出した周回が区間内の同じ位置に来た時刻との差）。未走行は空欄
4. `Best` 区間ごとのセッション内ベスト（別々の周回から集めた理論ベスト。合計を末尾に出すかは設定 `total = 0/1`）
5. 履歴: 直近の周回の区間タイム（`laps` 行）。区間ベストは `best` 色（LapWindow の ★ と同じ判定）

数字の書式は秒 `12.345`（60 秒以上は `1'02.345`）。走行中の経過時間も含め、小数以下は常に 3 桁にそろえる（`5.100`）。等幅の縁取り文字で、列は右揃え。

### 周回の種類ごとの表示
- **OUT ラップ**: 最初のライン通過までは `Time` を `--'--.---` とし、通過後から計測（LapAnalyzer のアウトラップの扱いと同じ）
- **IN ラップ・停止中（ピット）**: 最後の通過時点の表示を保持する。セッションが変わったら履歴とベストをリセットし、セッション情報を切り替える
- **無効の周回（×）・未完**: 履歴に `×` / `未完` と表示し、ベストの対象にしない

## 3. 設定ファイル（`*.overlay.ini`）

見本の `overlay_layout.ini` と同じ形式（`tk2nmea.ini` に合わせ、`;` は注釈、色は `#RRGGBB` / `#AARRGGBB`）。

- 座標・大きさは 1920×1080 を基準にした画素数で、ほかの解像度では比例して拡大縮小する
- 共通項目: `show` `anchor`（topleft / top / topright / bottomleft / bottomright）`x` `y` `scale` または `size` / `width` `height`
- メーター画像は、見えている範囲（不透明な部分）の端を基準に置く（`standard.png` は下 15% が透明な余白のため）
- 画像やフォントのパスは ini からの相対パスも可。メーターは VSD の `standard.png` を使う前提（決定済み）。VSD の画像なのでリポジトリ・配布物には入れず、ユーザーが ini の `image` で場所を指定する。見つからないときは代わりの画像（単色の円盤＋縁取り。半透明の暗い円に白っぽい縁）を描いて使い、書き出し画面にその旨を表示する（書き出しは止めない）。代わりの画像は standard.png と同じ 300×300・同じ配置（中心 150,150、見える範囲の下端 258）で作り、目盛りや針の位置が変わらないようにする
- 部品を別の部品の下に続けて置ける: `below = session`（その部品の下端から `y` だけ空けて置く。ラップ表はセッション情報の下に続ける。セッション情報を非表示にしたら、ラップ表は画面の端から `y` の位置に上がる）
- 追加する節: `[session]`（`size` `color` `jfont`。ドライバー名が空ならその部分を出さない。Impact には日本語の字形が無いので、日本語の名前は `jfont`（既定 Meiryo UI など）で描く。WPF ならフォントの代替指定 `"Impact, Meiryo UI"` で自動で切り替わる）、`[sector]`（`size` `laps` `total` `best` `plus` `minus`）、`[map]` に `gates = 1`, `gatecolor`, `controlcolor`, `gatewidth`（線はコース定義の中心線。現在位置はログの位置をそのまま打つ）
- 既定の ini を exe と同じフォルダに置き、書き出し画面で別の ini を選べるようにする。最後に使った ini は Settings に保存

## 4. 本体への組み込み

### 画面
- **LapWindow** に「動画素材を書き出す...」を追加。セッション一覧で選んだセッション（複数選択可）を対象にする
- 書き出し画面 `OverlayExportWindow`（新規、`Theme.ApplyDark` と `Settings.Track` を使う）
  - レイアウト ini の選択、解像度（1920×1080 / 3840×2160 / 動画に合わせる）、フレームレート
  - 範囲: セッション全体（最初のライン通過の少し前〜最後の通過の少し後、前後の余白秒を指定）または開始・終了時刻を指定
  - **プレビュー**: スライダーで時刻を動かすと 1 フレームを描いて表示。背景に動画の 1 コマ（静止画）を読み込める
  - 出力形式: ProRes 4444（`.mov`）／透明 PNG 連番／QuickTime Animation（`qtrle -pix_fmt argb` の `.mov`。可逆で、20 秒の試験で ProRes 288MB → 34.5MB。Resolve での透明は未確認）
  - ffmpeg のパス（PATH → 既定の場所 → 指定。見つからなければ PNG 連番だけ可能）
  - 進み具合とキャンセル

### 処理の流れ
1. 対象セッションのログ（`GpsSample` の列）、`LapAnalysis`、`CourseDefinition` を受け取る
2. 前処理（`OverlayData`）
   - 速度: ロガーの速度があれば使い、無ければ位置の差分から求める
   - **補間**: 時刻 t の位置・速度・高度を前後の点から線形補間（VSD の `SmoothLowFreqLog` と同じ考え方）。記録の途切れ（停止中）は前の値を保持し、速度 0
   - **G の算出**（Wintec は加速度センサーが無い）: 前後 G = 速度の時間微分、横 G = 速度 × 向きの変化率。1Hz では荒いので、前後数秒の移動平均をかける（平滑化の秒数は ini で指定）
   - ラップ・セクターの通過時刻の一覧（`LapRecord.StartT` / `EndT` / `Sector` から）
   - リアルタイム差分のための基準: セッション内ベストラップと、各区間のベストを出した周回について、「時刻 → コース上の進み具合（距離の割合）」の表を作る。ログの位置をコース中心線に投影して距離を求め、1Hz の間は線形補間する。差分は「今の経過時間 − 基準が同じ進み具合に達した時刻」
   - ベストは時間とともに変わる（セッション内でより速い周回が出たら、その周回の終了以降はそれが基準）。その時点までに走り終えた周回だけを基準にする（未来の周回を基準にしない）
3. フレーム n の時刻 t = 開始時刻 + n / fps でその時点の状態（`OverlayState`）を作る
4. 描画（`OverlayRenderer`）: WPF の `DrawingVisual` → `RenderTargetBitmap`（Pbgra32）。部品ごとのクラスに分け、ini の節と 1 対 1 に対応させる
5. 書き出し（`OverlayEncoder`）: ffmpeg を起動し、標準入力に生の画素を流す（`-f rawvideo -pix_fmt bgra`）。PNG 連番は `PngBitmapEncoder` で保存
   - WPF の描画は `Pbgra32`（乗算済みアルファ）なので、ffmpeg に渡す前に非乗算に戻すか、ffmpeg 側で扱いを合わせる（半透明部分の色が暗くならないことを確認する）
   - 描画は UI スレッド外で行う（`DrawingVisual` は専用の STA スレッドで作る）

### 必要な既存コードの変更
- `GpsSample` に高度（`Alt`）を足す（文字データの Alt 用。tk2 / NMEA GGA から）
- ログの通算秒 `T` を日本時間の日時に戻す基準（文字データの DateTime 用）を `GpsLoader` から取れるようにする
- `CourseDefinition` からラインの両端の座標を取る（すでに KML 用にあるものを使う）
