# 解析データのまとめ方（ライブラリ）と動画比較の別アプリ化 設計メモ

2026-11-18 作成。同日、10 章の方針をユーザーが決定。まだ実装していない（計画の段階）。

ラップ解析で使うデータ（コース定義・GPS ログ・解析の入力と結果・動画・心拍など）を 1 つのフォルダの階層にまとめ、フォルダごと移しても使い続けられるようにする。
まとめたデータの中から好きな周回を選んで動画で比べる画面を、別のアプリとしても起動できるようにする。

位置付け:
- **WintecTK2Converter**（今のツール）= データを**作る**ツール。変換・コース定義・ラップ解析・動画の時刻合わせ・音声解析・心拍・素材の書き出し
- **動画比較アプリ**（新規）= まとめたデータを**見る**ツール。部品は共通

---

## 1. 現状の整理

### 1.1 いまのファイルの置き方

ログの横に「ログ名 + 拡張子」の付属ファイルを置く方式。ログが書き込めない場所なら一部は `%LOCALAPPDATA%\WintecTK2Converter\` に退避する。

| ファイル | 中身 | 何で対応付けているか | 移動したとき |
|---|---|---|---|
| `*.course.json`（+ `.kml`） | コース定義 | ラップ解析の画面で毎回選ぶ（最後に使ったものを設定に覚える） | `sources`（作るのに使ったログ）が**フルパス** |
| `ログ.drivers.json` | セッションのドライバー名 | セッションの時刻の重なり | ○（退避先に置いた分はパスの hash で探すので ×） |
| `ログ.sessions.json` | セッションの手動分割・結合 | キー = ログの**フルパス**（小文字） | 中身は時刻なので○、退避先は × |
| `ログ.runs.json` | ジムカーナの走行のメモ・ドライバー・印 | 走行の開始時刻 ±5 秒 | ○（退避先は ×） |
| `ログ.videos.json` | 動画の t0・長さ・切り出し元 | 動画の**フルパス**、時刻はログの通算秒 | **×**（動画のパスが絶対） |
| `ログ.heart.json` | FIT の心拍（記録を丸ごと写す）と offset | **セッションの番号** | FIT のパスは絶対（表示には使わない） |
| `ログ.engine.json` | 車の設定（ギア比など）＋動画ごとの音声解析の結果 | ログの通算秒・動画のパス | 動画のパスが絶対 |
| （無し） | ラップ解析の結果 | 保存しない。毎回ログとコース定義から計算し直す | ― |
| 設定 `WintecTK2Converter.settings.json` | 停止とみなす秒数など解析の条件 | **アプリ全体で 1 つ** | ― |

### 1.2 動画比較の今の制限

今の「▶ 動画で比較...」は、ラップ解析の周回表で選んだ 2 つの周回を、それぞれのログの `videos.json` から動画を探して並べる。周回ごとに別の動画を使うので、**同じログの別の動画どうし**や、**ラップ解析に複数のログを入れていれば別のログどうし**も、実は今でも比べられる。

本当の制限は次のとおり。

1. 比べたいログを全部、同じコース定義で、同じラップ解析の画面に入れ直して解析しないと選べない（どこに何があるかの一覧が無い）
2. 動画・FIT のパスが絶対なので、フォルダを移すと動画が見つからなくなる
3. 心拍が「セッションの番号」で結び付いているので、停止の秒数を変えたり手動で分割・結合したりして番号がずれると、別のセッションに付いてしまう
4. 解析の条件（停止の秒数など）がアプリ全体の設定なので、別の条件で解析し直すとセッションの切れ目・番号が変わり、後から同じ結果を再現できない
5. 比べられるのは 2 本まで（A / B 固定）。これは今回は変えない（10 章）
6. 比較の画面がラップ解析の画面からしか開けない

1・2 は「まとめ方」が無いこと、3・4 は「何を基準に結び付けるか」の不統一が原因。ここを直さないと、まとめても移動や再解析で壊れる。

## 2. 設計の原則

1. **結び付けは「ログの時刻」で行う**。ログの通算秒（2000-01-01 UTC からの秒）は再解析しても変わらない。セッションの番号・周回の番号は表示用で、保存のキーにしない
2. **保存するパスはすべて、その JSON ファイルのあるフォルダからの相対パス**。フォルダの外を指すときだけ絶対パスを許し、「外部参照」と印を付ける（移すと切れることを画面で知らせる）
3. **1 ログの付属情報は 1 か所**。ログの横にまとめて置く。`%LOCALAPPDATA%` への退避はやめる（書き込めない場所のログは「まとめる」で書ける場所へ移してもらう）
4. **解析の入力（条件・手動の編集・人が入れた情報）を正とし、解析の結果はキャッシュ**。結果にはコース定義と条件の「指紋」を付け、合わなければ計算し直す。ログが手元にあるので、いつでも同じ結果を作り直せる
5. **階層は決まりごとではなく「置き方の既定」**。ログの付属ファイルがコース定義と動画を相対パスで指していれば、どこに置いても動く。階層どおりに置くと、フォルダごとの移動・一覧の作成が楽になる

## 3. フォルダの階層

```
D:\Racing\                                   ← ライブラリの最上位（任意。比較アプリでここを開く）
└─ RainbowSports\                            ← コースフォルダ（= 走る場所とレイアウト）
   ├─ RainbowSports.course.json              ← コース定義（基本のセクター条件）
   ├─ RainbowSports.kml
   ├─ RainbowSports.5sector.course.json      ← 同じ場所でセクターだけ違う定義（任意。4 章）
   ├─ 2026-11-07_20261107\                   ← ログフォルダ（1 ロガーの 1 日分）
   │  ├─ 20261107.nmea                        ← GPS ログ（元データのまま）
   │  ├─ 20261107.nmea.log.json               ← 解析の入力（条件・手動の編集・ドライバー・メモ・動画の t0・車・心拍の対応）
   │  ├─ 20261107.nmea.rpm.json               ← 音声から求めた回転数の列（大きいので分ける）
   │  ├─ 20261107.nmea.laps.json              ← 解析の結果（キャッシュ。コース定義ごと。段階 2）
   │  ├─ 20261107.csv                         ← CSV（任意）
   │  ├─ heart\
   │  │  └─ 竹佐さん 最終枠.FIT
   │  └─ videos\
   │     ├─ Rainbow3_Re.mp4
   │     └─ clips\                            ← このツールで切り出した動画
   │        └─ S6_L8.mp4
   └─ 2026-10-25_MAH00931\
      └─ ...
```

- **コースフォルダ** = 物理的に同じ場所・同じレイアウト。中に 1 つ以上のコース定義を置ける。ジムカーナは大会ごとにパイロンの配置が変わるので、**大会（配置）ごとに 1 フォルダ**
- **ログフォルダ** = 1 つのログファイルとその付属物。1 ログは 1 台のロガー = 1 台の車
- **動画** = 1 つの動画は 1 つのログの一部（何周か・何本か）を映している。1 つのログに動画は何本あってもよい。同じ周回を映した動画が複数あってもよい（ヘルメットカメラと車載など）
- **FIT** = 腕時計 1 つ分の記録。ログのセッションに時刻で結び付ける。1 つの FIT が 1 セッション、1 ログに何個でも

役割はフォルダ名ではなく、中のファイルで見分ける（`*.course.json` があればコースフォルダ、`*.log.json` があればログフォルダ）。名前は自由に付け直してよい。

## 4. コース定義と「同じセクター条件」

### 4.1 コース定義の指紋と ID

`*.course.json` に次を足す。

- `id`: コース定義を作ったときに振る GUID。ファイル名を変えても同じ定義と分かる
- 指紋（保存しない。読むたびに計算）: `mode`・ゲート（ライン）の座標・片側の幅の hash。中心線は表示用なので含めない

ラップ解析の結果（`laps.json`）には、使ったコース定義の `id` と指紋を記録する。開いたときに指紋が違えば「コース定義が変わったので解析し直します」と出して計算し直す。

### 4.2 ラインを直したとき・セクターを変えたいとき

| したいこと | やり方 | 既存の解析 |
|---|---|---|
| コントロールラインの位置を直す（同じ条件のつもり） | 同じファイルを上書き保存（`id` は同じ） | 全ログが「指紋違い」になり、開いたときに計算し直す |
| 別のセクターの切り方でも見たい（公式のセクターと自分のセクターなど） | 「別の条件として保存」= 同じコースフォルダに別の `*.course.json`（新しい `id`） | 元の定義の結果はそのまま。新しい定義の結果は別に作る |
| 別のコース（別の場所・ジムカーナの別の配置） | 新しいコースフォルダ | ― |

比べられるのは**同じコース定義（同じ `id`）で解析した周回どうし**。セクターで揃える再生があるので、ラインが違う周回は混ぜない。

> 決定（2026-11-18）: ルート = 場所とレイアウトとし、その中にセクター条件を複数置ける。当初の案は「ルート = セクター条件」だったが、それだとセクターだけ違う定義のためにログと動画を丸ごと別のフォルダへコピーすることになり、動画が二重になる。同じ条件の結果を集めるという目的は、コース定義の `id` で満たせる。

### 4.3 ログとコースの対応

`log.json` に、使うコース定義を相対パスで書く（通常は `..\RainbowSports.course.json`）。複数の定義で解析したら全部書く。ログフォルダだけを別のコースフォルダへ移した場合は、そのフォルダのコース定義を使うかを尋ねる。

## 5. ファイルの形式

すべて UTF-8・インデント付き（心拍・音声解析の配列は 1 行でよい）。`format` と `version` を必ず持つ。

### 5.1 `ログのファイル名.log.json`（解析の入力。正。段階 1 で実装済み、gui/LogFile.cs）

今の `drivers / sessions / runs / videos / heart` と、アプリ全体の設定にあった解析の条件・`engine.json` の車の設定をまとめる。
名前は拡張子まで含めたログのファイル名 + `.log.json`（例 `20261107.nmea.log.json`）。tk2 から変換した同じ名前の nmea と混ざらないため。

```json
{
  "format": "WintecTK2Log", "version": 1,
  "log": "20261107.nmea",
  "imported": ["20261107.nmea.drivers.json", "..."],
  "params": { "pitStopSec": 30, "minCrossSpeedKmh": 8, "slowLapRatio": 1.25 },
  "sessionEdits": { "splits": [847348920.98], "merges": [] },
  "drivers": [ { "startT": 847348920.98, "endT": 847349404.996, "driver": "takesa" } ],
  "runs": [ { "startT": 847350000.0, "driver": "...", "memo": "...", "mark": "..." } ],
  "videos": [ { "path": "..\\2026-11-07\\MAH00948.MP4", "t0": 847348540.04, "duration": 915.41, "overlay": false } ],
  "heart": [
    { "fit": "heart\\20261107 竹佐さん 最終枠.FIT", "device": "Polar Ignite", "startT": 847348901.7, "endT": 847349442.7,
      "offset": 347948.7, "auto": 347948.7, "candidates": [ ... ] }
  ],
  "engine": { "vehicle": "kart", "rpmPerKmh": 167.7, "manual": true, "...": "..." }
}
```

- 書かれていない項目は省く。この版が知らない項目は書き戻すときに残す。一時ファイルに書いてから置き換える。壊れていれば上書きしない
- `params` をログごとに持つ（4 章の指紋と並んで、結果を再現するのに必要）。サーキットの解析のたびに保存し、ログをラップ解析の画面に入れたときに画面へ戻す。ログごとに違えば最初のログの値を使って知らせる。新しいログの初期値は、今までどおり画面の値
- `videos` は動画を登録した一覧（t0・長さ・切り出し元・焼き込みの有無）。パスは相対
- `courses`（使うコース定義）と `logger`（記録の間隔など）は段階 2 で足す
- `heart` の結び付けは**セッションの番号をやめて時刻の範囲**（ドライバー名と同じ方式）。心拍の記録そのもの（今は `heart.json` に写している `t` / `bpm`）は**写しを持たず、FIT から毎回読む**（決定）。そのため FIT は必ずログフォルダの `heart\` にコピーする。まとめていないログでも、時刻合わせの画面で「FIT を開く...」をしたときに、ログの横の `heart\` へコピーしてから登録する（元の FIT は動かさない）。`fit` は `heart\` からの相対パスだけ。FIT が見つからないときは、その心拍を出さずに知らせる
- `car` は 1 ログ = 1 台なので、ログに 1 つ

### 5.2 `ログ名.laps.json`（解析の結果。キャッシュ）

```json
{
  "format": "WintecTK2Laps", "version": 1,
  "results": [
    { "course": "<コース定義の id>", "courseHash": "...", "paramsHash": "...", "analyzed": "2026-11-18T21:00:00+09:00",
      "sectorNames": ["S1", "S2", "S3"],
      "sessions": [ { "startT": ..., "endT": ..., "driver": "...", "laps": [ { "startT": ..., "endT": ..., "type": "Normal", "valid": true, "lapTime": 41.611, "sectors": [...], "maxKmh": ..., "note": "..." } ] } ] }
  ]
}
```

- 比較アプリの一覧は、GPS を読まずにこれだけで作れる（ログが何十本あっても速い）
- 指紋（`courseHash`・`paramsHash`・ログファイルの大きさと更新日時）が合わなければ、ログとコース定義から計算し直して書き直す
- 周回を指す ID = **ログフォルダ + コース定義の id + 周回の開始時刻**（ミリ秒で丸め）

### 5.3 `ログのファイル名.rpm.json`（音声から求めた回転数。段階 1 で実装済み）

`engine.json` の区間の列（動画ごとの rpm・throttle・tone）。大きいので log.json と分ける。`video` は相対パス。

> 実装時の変更（2026-11-18）: 当初は動画ごとに `動画名.video.json` を動画の横に置く案だったが、
> 「1 ログの付属情報は 1 か所」に揃えるため、動画の t0 などは `log.json` の `videos` に、回転数の列はこの `rpm.json` に置いた。
> ユーザーの動画フォルダに付属ファイルを散らさずに済み、動画は `log.json` から相対パスでたどれる。
> 「まとめる」（段階 3）で動画を `videos\` に置けば、ログフォルダごと移せる。`videos\` の外の動画は相対パスのまま参照し、届かなければ見つからない旨を出す

### 5.4 アプリ全体に残すもの

ウィンドウの位置、ffmpeg の場所、表示のレイアウト（`*.overlay.ini`）、車両のセット（`cars.json`）、最後に開いたフォルダ。データの解釈に関わるものは置かない。

## 6. 「データをまとめる」機能（作るツール側）

ラップ解析の画面に「データをまとめる...」を足す。

1. まとめ先のコースフォルダを選ぶ（新規なら作る。コース定義をそこへ置く。今使っているコース定義と同じ `id` が既にあればそれを使う）
2. 解析に入れているログごとにログフォルダを作り（名前の既定は `日付_ログ名`）、ログを移す / コピーする
3. 今の付属ファイル（`drivers / sessions / runs / heart / engine / videos`、`%LOCALAPPDATA%` に退避してある分も）を読み、新しい形式に書き換える。心拍のセッション番号は、今の解析結果で時刻の範囲に直す
4. そのログに登録されている動画・切り出しを `videos\` に、FIT を `heart\` にコピーする。**既定はコピー**（決定）。動画は画面で「移動」「元の場所を参照（外部参照）」にも変えられる。FIT は常にコピー
5. 解析の結果（`laps.json`）を書き、まとめた先で開き直して、周回数・動画の数・心拍の数が元と同じかを確かめて結果を出す
6. 古い付属ファイル（と、コピー元のログ・動画・FIT）は**消さず、名前も変えずに残す**（決定）。消すのは後でユーザーが手で行う。まとめた先を開くときは、まとめた先のファイルだけを読む

動画は大きい（AV1 1080p60 で数 GB）。コピーが既定なので、始める前にコピーする量とコピー先の空き容量を出し、足りなければ止める。コピーには時間がかかるので、進み具合とキャンセルを付ける。キャンセルしたときは、途中まで書いたファイルを消す。

まとめた後も、作るツールの各画面（時刻合わせ・音声解析・心拍・書き出し）は新しい形式に読み書きする。まとめていないログも同じ新形式（`ログ名.log.json` をログの横に置く）で扱い、古い付属ファイルは最初に開いたときに取り込む。**新旧 2 つの保存方法を並べて持たない**。

## 7. 動画比較アプリ

### 7.1 起動と構成

- プロジェクトを分ける:
  - `core\`（クラスライブラリ、net10.0-windows・WPF）… 形式の読み書き（tk2nmea.cs のリンクも）、ストア、ラップ解析、表示の描画（OverlayRenderer など）、ffmpeg（FfVideo）、VideoPane、WaveOutPlayer、ReplayWindow、テーマ・アイコン・設定の仕組み
  - `gui\`（今のツール）… core を参照
  - `compare\`（新規、`LapVideoCompare.exe` などの名前）… core を参照。ライブラリの一覧と動画比較の画面
- 作るツールの「▶ 動画で比較...」も、同じ比較の画面（core の `VideoCompareWindow`）を開く
- 2 つの exe は同じ発行フォルダに置く。設定ファイルはアプリごとに分け、ffmpeg の場所・表示のレイアウトは作るツールの設定を読みに行く（無ければ自分の設定）
- 比較アプリは**別の exe にする**（決定）。ただし先に、作るツールの exe を `-compare フォルダ` で起動すると比較アプリの画面だけが開く形で作り（段階 4）、プロジェクトの分割と exe の作成はその後に行う（段階 5）

### 7.2 画面

```
┌ ライブラリ ────────────────┐┌ 選んだ周回 ─────────────────────────┐
│ D:\Racing\                  ││ A  11/07 S6 L8  竹佐  0'41.611  Rainbow3_Re.mp4 │
│ ▼ RainbowSports [基本]      ││ B  10/25 S2 L5  竹佐  0'42.010  MAH00931.MP4    │
│   ▼ 2026-11-07_20261107     ││          [動画を選ぶ ▼] [外す]                   │
│     ▼ S6 竹佐  🎥 ♥         ││                                                 │
│        L8 0'41.611 ★ 🎥     │└──────────────────────────────┘
│        L9 0'41.900   🎥     │ 絞り込み: ドライバー [  ] 日付 [  ] □ 動画のある周回だけ
│   ▶ 2026-10-25_MAH00931     │ 並べ方: ベスト順 / 時刻順
└─────────────────────────────┘           [▶ 動画で比較]  [地図で比較]
```

- ライブラリの最上位（またはコースフォルダ）を開くと、`*.course.json` と `*.log.json` を探して木を作る。一覧は `laps.json` から作る（古ければ裏で解析し直す）
- コース定義（条件）を 1 つ選び、その条件の周回だけを並べる。コース全体のベスト（全ログ通し）も出せる
- 周回ごとに、その周回が映っている動画の有無を出す。複数あれば選べる（今の `Find` は「一番短く全体が入るもの」を自動で選ぶが、これを既定にして変えられるようにする）
- 動画の無い周回も選べる（地図だけで比べる。今の比較再生と同じ）
- 比べるのは**今と同じ 2 本（A / B）**（決定）。一覧で周回をクリックすると、空いている方（A、次に B）に入る。入れ替え・外すもできる

### 7.3 比較の中身（今の方式を引き継ぐ）

- 時計は「周回の開始（またはセクターの開始）からの秒 τ」。それぞれの動画の時刻 = 周回の開始 + τ − 動画の t0（今と同じ）
- 表示を重ねるときの「ベスト」「履歴」は、それぞれの周回が属するセッションのもの（`laps.json` のセッションから作る）。別の日の周回どうしでも矛盾しない
- 心拍・回転計は、それぞれのログの `log.json`・`rpm.json` と `heart\` の FIT から
- 音声は今と同じ「両方 / A / B / 左右 / なし」

## 11. 残る心配・未確定

- 1 つのログに別のコース（午前は A サーキット、午後は B）が入っている場合: ログフォルダは 1 つのコースフォルダにしか置けない。必要ならログを分割する機能（時刻で切る）を足す。今のところ実例が無いので後回し
- 1 つの動画が 2 つのログにまたがる場合（ロガーを途中で替えた等）: 動画は 1 つのログに属させ、もう一方からは外部参照にする
- 2 台のロガー（Wintec と 5Hz）で同じ走行を取った場合: 別のログフォルダ。比べるときは別の周回として並ぶ
- 個人のログ・動画を含むので、ライブラリはリポジトリの外に置く（今の方針どおり）
- Google Earth 用の KMZ の出力先は、今は変換の画面で決めている。ログフォルダに置くかは別に考える
