tk2nmea (C#版) - Wintec TK2 → NMEA / KMZ 変換ツール（GPS週番号ロールオーバー補正付き）

■ WPF 版（画面付き: WintecTK2Converter.exe）
  build_gui.bat をダブルクリックすると gui\publish\WintecTK2Converter.exe ができます。
  （ビルドに .NET SDK 10、実行に .NET 10 デスクトップ ランタイムが必要です）
  起動すると「変換ツール」「解析ツール」を選ぶ画面が出ます（1.7.0 から）。
    ・変換ツール: 下の変換の画面（メイン画面）が開きます
    ・解析ツール: 「コース定義を作成...」「ラップ解析...」「ライブラリから比較...」を選びます
  開いた画面を閉じると、この選ぶ画面に戻ります（選ぶ画面を閉じると終了）。
  exe に .tk2 やフォルダをドロップしたときは、選ぶ画面を出さずに変換の画面が開きます。
  「-course」「-lap」「-compare」を付けて起動すると、その画面だけが開きます。
  1. 変換ツールを開き、 .tk2 ファイル（複数可）またはフォルダをウィンドウへドラッグ＆ドロップ
     （「ファイルを追加...」「フォルダを追加...」ボタン、exe へのドロップでも追加できます）
  2. 一覧で選んだファイルの記録範囲と停止区間（60 秒以上記録なし）が左下に出ます
  3. 前後をカットしたいファイルは「開始カット」「終了カット」欄に現地時刻を入力（例 08:05:00）
     空欄ならカットしません。ファイルごとに別々に指定できます
  4. 右側で出力先・出力形式（KMZ / KML / NMEA のみ）・RMC の日付（日本時間にするか）・
     高さの表示・ツアーの有無・補正週数を選び、「変換する」を押す
  5. 結果は下のログ欄に出ます。「出力フォルダを開く」で出力先を開けます
  画面の初期値は tk2nmea.ini の内容です。画面にない細かい設定（Km ポスト、速度の色分け、
  ツアーのカメラなど）は、exe と同じフォルダの tk2nmea.ini で変更します。
  以下の「使い方」はコンソール版（tk2nmea.exe）の説明です。

■ コース定義の作成（WPF 版の「コース定義を作成...」）
  サーキット（周回コース）を走ったログから、コースの中心線・コントロールライン・セクターラインを作ります。
  今後のラップ・セクタータイム計測や、Google Earth での確認に使うファイルです。
  1. 解析ツールの「コース定義を作成...」を押す
     走行ログ（.tk2 / .nmea、複数可）を追加。周回が多いほど精度が上がります
     exe に「-course ファイル...」を付けて起動しても、この画面が開きます
  2. 「解析する」: 周回を重ね合わせて平均化し、中心線を求めます
       ・速度の下限（既定 18 km/h）より遅い点（ピット・停止・低速でばらつく所）は使いません
       ・周回ごとに所要時間・欠測を調べ、中央値の 1.2 倍を超える周回（ピットイン等）を除きます
       ・点そのものを使うので、1 秒間隔でもカーブを切り込みません
  3. 右のプレビューで確認（赤=中心線, 青=採用した周回, 橙=除外した周回, 矢印=進行方向）
     右上の「航空写真」にチェックすると、背景に国土地理院の航空写真を出します（比較再生と同じ写真。初回だけインターネットから取得）
  4. コントロールライン（スタート/ゴール）とセクターラインの位置を調整
     自動では、コントロールラインを停止・低速の点が多い所（ピット付近）に、セクターを周長の等分位置に置きます
     一覧で選んだライン 1 本だけを、スライダー・数値入力・±1m / ±5m ボタンで前後に動かせます（選んだラインは青で表示）
     地図をクリックしても、選んだラインをいちばん近い中心線の位置に置けます。近くを何度も通る所では、通るごとに候補ができ、
     ホイールか Tab（Shift+Tab で戻る）で切り替えます（候補は地図に番号付きの丸、何 m 目・向きを下に表示）
     「自動位置に戻す」で選んだラインを既定の位置へ、「等間隔に配置し直す」でセクター数を変えて全体を置き直します
  5. 「Google Earth で重ねて確認」: 中心線・ライン・元データを KML で開きます
     GPS の位置は実際より数 m ずれることがあるので、衛星写真と見比べて確認してください
  6. 「コース定義を保存...」: *.course.json（コース定義）と同名の .kml を保存します
     コース定義には ID が付きます（1.5.1 から。前の版の定義は、開いたときに ID を足して書き戻します）。
     同じファイルに上書きすると同じ条件（同じ ID）のままで、ラインを直したときは次のラップ解析で解析し直されます。
     「別の条件として保存...」は新しい ID で保存します（公式のセクターと自分のセクターなど、同じ場所で別の切り方も見たいとき）。
     元の定義で解析した結果はそのまま残り、新しい定義の結果は別に作られます
  コース定義ファイル（JSON）: コース名, 周長, 回転方向, 中心線（約 2m ごとの緯度経度）, ゲート（コントロールライン
  とセクター。両端の緯度経度）, 解析の統計（採用周回数・ばらつき）, 元ログのパス。「保存済みのコース定義を開く...」で読み込めます（元ログが見つかれば、入力の一覧にも戻ります）。
  走行ログの一覧は画面を閉じるときに覚え、次にログを指定せずに開いたときに戻ります（残っているファイルだけ）

  ジムカーナのコース（「解析の設定」の種類で「ジムカーナ」を選ぶ）:
  スタートとフィニッシュが別の所にあるコースです。周回を平均化せず、走行を 1 本ずつ切り出して、1 本を基準にします。
  1. 走行ログを追加して「解析する」
       ・止まった所から一気に加速した所を発進、フィニッシュ後のスロー走行（遅い状態が 8 秒続く）に入った所を走行の終わりとします
         （待機列で少しずつ進むのは発進にしません。サイドターン・スラロームの減速は短いので走行は途切れません）
       ・発進位置と距離が同じような走行を「同じコースの走行」として自動でチェックします
  2. 「走行 (ジムカーナ)」の一覧で、使う走行のチェックと、中心線にする「基準の走行」を選び直せます
       ・時間・距離はフィニッシュの目安（最後に 30 km/h を超えた所）までの目安です。※ は自動で外した走行（理由はツールチップ）
       ・チェックや基準を変えると、スタート・フィニッシュは自動の位置に置き直します
  3. スタート（緑）は発進前に止まっていた位置の少し先、フィニッシュ（白）は最後に速く走っていた所に自動で置きます
     サーキットと同じように、一覧で選んだラインを距離・地図のクリックで動かせます。セクターはスタートとフィニッシュの間の等分です
     解析した直後は、基準の走行の時刻と速度を使って置くこともできます（保存済みのコース定義を開いたときは使えません）
       ・地図クリックの候補に「スタートから何秒目・速度」も出します。一覧の各ラインにも何秒目かを出します
       ・「スタートから [ ] 秒目」→「この時刻に置く」: 車載動画を見ながら決める用
       ・「速度の極小点」: 基準の走行で速度が落ちた所（サイドターン・スラロームなど）の一覧。選ぶとそこに置きます
       ・地図の下の「距離 → 速度」のグラフ: マウスを乗せると距離・秒・速度を表示、クリックでその距離に置きます（▲ = 速度の極小点）
       ・セクターはスタートとフィニッシュの間にだけ置けます。動かした後は距離の順に Sector1, 2, … と付け直します
     ラインの片側の長さは既定 12 m（同じ所を通る別の通過は、向きと走行距離で区別します）
  4. 保存・Google Earth での確認はサーキットと同じです
  5. 「このコースでラップ解析...」（または保存したコース定義をラップ解析で開く）で、走行ごとのタイムを計算します
       ・1 つのログが 1 セッション、走行は「1本目」「2本目」…と並びます。タイム・区間タイム・ベストとの差・最高速
       ・スタートは止まった状態から通ったときだけ数えます。そのあと、ラインを順番どおり・同じ向き・
         コースの距離に合う所で通ったときだけ数えます（同じ所を何度も・逆向きに通っても取り違えないため）
       ・DNF: フィニッシュしなかった走行（基準タイムの 3 倍を過ぎた、次のスタートが来た、ログが終わった）
       ・ミスコースの疑い: 途中のラインを通らなかった走行（タイムは出しますが、ベストの対象外）
       ・停止を含む: 途中で止まった走行（スピンなど。タイムはそのまま）
       ・上の要約に、全体のベストと理論ベスト（各区間のベストの合計）を出します
       ・セッションの分割・結合はありません。比較再生・CSV 保存（Type 列が RUN / DNF / MISS）はサーキットと同じです
  6. 走行一覧で走行を 1 本選ぶと、下の欄でメモ・ドライバー・印を入力できます（自動で保存。タイムには反映しません）
       ・メモ: 自由に書けます。「パイロンタッチ +1」（押すたびに ×1, ×2…と増える）「脱輪」「ミスコース」「スピン」のボタンで素早く入れられます
       ・ドライバー: その走行だけのドライバー（1 台を何人かで乗るとき）。空ならセッションのドライバー
       ・印: 自動（通過の判定どおり）／有効（ミスコースの疑いでもベストの対象にする）／ミスコース扱い（ベストの対象外にする）
       ・保存先は、ログの付属情報（ログファイルのそばの「ログ名.log.json」。下の「ログの付属情報」）。次に解析したときに戻ります
       ・CSV にはドライバー・ベストとの差（Gap）・メモも出します
  7. 複数の人・複数のロガーの比較: 同じコース定義で、ログを何本でも追加して解析します（1 つのログが 1 セッション）
       ・★ = 全ログ通しての最速、※ = そのドライバーの最速（ドライバー名が無い走行はログごと）。ドライバー名を変えると付け直します
       ・「タイム順 (全ログ)」にチェック: 全ログの走行をタイムの速い順に 1 つの表にし、「1位」「2位」…を付けます（ミスコース・DNF は後ろ）
       ・比較再生・距離ごとの比較（下の 8e）・動画素材の書き出しも使えます。動画素材のタイム表は「何本目」、ドライバーは走行ごとの名前です

■ ラップ・セクタータイム（WPF 版の「ラップ解析...」）
  コース定義（コントロールライン + セクターライン）と走行ログから、ラップタイムとセクタータイムを計算します。
  コース定義の作成画面の「このコースでラップ解析...」からも開けます。
  exe に「-lap コース定義.course.json ログ...」を付けて起動しても、この画面が開きます。
  1. コース定義 (*.course.json) を開き、走行ログ (.tk2 / .nmea) を追加して「解析する」
  2. 区間: S1 = コントロール → Sector1, S2 = Sector1 → Sector2, ... 最後の区間はコントロールラインで終わります
     通過時刻は、各点の間の線分とラインの交点を求め、距離の比で補間します（逆向きの通過・低速でのふらつきは無視）
  3. アウトラップ: 最初に通ったラインから計測します。Sector1 のラインから始まれば S1 は空欄で（備考は「Sector2 から計測」）、ラップタイムは出さず（OUT）、
     ベストの対象にもなりません。停止からの発進でコントロールラインから始まる周回も OUT です
  4. ピットイン: 一定時間（既定 30 秒）以上止まっていたら、そこでセッションを分けます（ドライバー交代など）
     ロガーが止まっている間は記録しない場合も、停止として扱います
       ・コントロールライン通過後に止まった場合: 通過した周回が IN ラップ
       ・コントロールラインに着く前に止まった場合: その周回は「未完」の IN（S1〜 は残ります）
     コントロールラインは、止まる位置（ピット）より手前に置いてください。コース定義の自動配置は停止位置の手前です
  4b. 停止の判定とセッションが食い違うときは、周回表を右クリックして手動で直せます
     ・周回の行 → 「この周回の前でセッションを分割」（止まっていない場所でも分けられます。コントロールラインから始まる周回の前で分けると、前のセッションの最後の周回は最後まで計測されて IN ラップになり、
       分けたあとの最初の周回はピットアウトとして OUT（備考「アウトラップ (Sector1 から計測)」）になり、ラップタイムは出しませんが、
       その周回のセクターは S1 から計測されます）
     ・セッションの行（区切り行）または周回の行 → 「前のセッションと結合」（停止の判定で分かれたセッションをつなげます。
       停止はなかったものとして、前のラインの通過（例: コントロールライン）から計測を続けます。停止の時間はその区間に入るので、
       その周回は「結合: 停止を含む周回」と注記され、ベストの対象外になります。手動で分けたところに使うと、その分割が取り消されます）
     ・「このログの分割・結合をすべて取り消す」
     編集すると自動で再解析されます。編集はログごとに保存され、「停止とみなす秒数」を変えても保たれます。
     保存先は、ログの付属情報（ログファイルのそばの「ログ名.log.json」）。
  5. セッションごとにドライバー名を入力できます（入力すると自動で保存され、次に同じログを解析したときに復元されます）
     保存先は、ログの付属情報（ログファイルのそばの「ログ名.log.json」）。
     セッションの時間範囲で対応づけるので、「停止とみなす秒数」を変えてセッションの分かれ方が変わっても引き継がれます。名前を消すと保存も消えます
  5b. ログの付属情報（1.5.0 から）: ログごとに、ログファイルのそばに「ログのファイル名.log.json」（例: 20261107.nmea.log.json）を 1 つ作り、
     解析の条件・セッションの分割と結合・ドライバー名・ジムカーナの走行のメモ・動画の時刻合わせ・心拍・車の設定をまとめて保存します。
     音声から求めた回転数は「ログのファイル名.rpm.json」、心拍の FIT はログのそばの heart フォルダにコピーして使います。
     ・中のパス（動画・FIT）はこのファイルからの相対で保存するので、ログのフォルダと動画のフォルダの位置関係を変えなければ、まとめて移しても使えます
     ・解析の条件（停止とみなす秒数・通過の最低速度・遅い周回の倍率）は、解析するたびにログごとに保存し、次にそのログを入れたときに画面へ戻します
       （ログごとに条件が違うときは、最初のログの値を使い、ログ欄に知らせます。解析すると画面の値で全部のログを解析して保存します）
     ・前の版の保存ファイル（ログ名.drivers / sessions / runs / videos / heart / engine.json と %LOCALAPPDATA% に退避したもの）は、
       最初に開いたときに取り込みます。元のファイルは消さずに残します（不要なら後で手で消してください）
     ・ログのそばに書き込めない場所では保存できません（ログ欄に理由を出します）。書ける場所へログを移してください
     ・解析の結果は「ログのファイル名.laps.json」に、コース定義（ID）ごとに保存します（1.5.1 から。後で作る比較アプリの一覧用）。
       ドライバー名や走行のメモを変えたときも書き直します。コース定義のラインが前と違えば、ログ欄に知らせて置き換えます。
       消しても、次に解析すれば作り直されます。log.json の courses には、解析に使ったコース定義を相対パスで記録します
  5c. 「データをまとめる...」（1.6.0 から。解析した後、左の「結果の保存」の欄）: コースフォルダ（走る場所とレイアウト）の下に
     ログごとのフォルダ「日付_ログ名」を作り、ログ・付属情報（log.json / rpm.json / laps.json）・心拍の FIT（heart\）・
     動画（videos\、切り出した動画は videos\clips\）を置きます。コース定義もコースフォルダに置きます（同じ ID のものが既にあればそれを使います）。
       コースフォルダ\
         コース名.course.json / .kml
         2026-11-07_20261107\
           20261107.nmea, 20261107.nmea.log.json, .rpm.json, .laps.json, heart\, videos\, videos\clips\
     ・まとめた後は、コースフォルダ（またはその上のフォルダ）ごと別の場所・別のドライブへ移しても、そのまま使えます
     ・動画は「コピー」（既定）・「移動」・「元の場所を参照」から選べます。始める前にコピーする量と空き容量を出し、足りなければまとめません
     ・中止したり失敗したりしたときは、その回に作ったファイルを消します。元のファイル（ログ・古い付属ファイル・動画・FIT）は消しません
       （「移動」のときだけ、全部うまくいった後で元の動画を消します）
     ・終わると、まとめた先を読み直して、セッション・動画・心拍・回転数の数が元と同じかを出します。「まとめた先をラップ解析で開く」で続けて使えます
  5d. 「ライブラリから比較...」（1.7.0 から。解析ツールのボタン、または exe に「-compare フォルダ」を付けて起動するとこの画面だけが開きます）:
     まとめたフォルダ（ライブラリの最上位、またはコースフォルダ）を開くと、コース定義（条件）ごとに、全部のログの周回を並べます。
     ・一覧は各ログの laps.json から作ります。無い・古い（コース定義のライン・解析の条件・ログが変わった）ログは、その場で解析し直します
     ・★ = その条件での全ログ通しのベスト、※ = セッションのベスト。「動画」の列のカメラの印 = 周回が丸ごと映っている動画がある（2 本以上なら数も出る）、♥ = 心拍を合わせたセッション
     ・ドライバー・日付で絞り込み、「動画のある周回だけ」、ベスト順 / 時刻順に並べ替えができます
     ・周回をダブルクリックすると空いている方（A、次に B）に入ります（「選んだ行を A に / B に」「入れ替え」「外す」も）。別の日・別のログの周回どうしでも比べられます
     ・動画が複数あるときは、A・B それぞれ「動画」の欄で選べます（既定は、周回が丸ごと入る一番短い動画）
     ・「▶ 動画で比較」はラップ解析の「動画で比較」と同じ画面（表示のベスト・履歴・心拍・回転計は、それぞれの周回のセッション・ログのもの）。「地図で比較」は動画なしで比較再生します
     「全セッションを続けて表示する」で、セッションごとの区切り行つきで一覧できます
     表示を広く使うための折りたたみ:
       ・「セッション一覧」「周回表」の見出し左の ⌃ で、それぞれ畳めます（畳むと、もう一方が広がります）
       ・全セッション表示では、区切り行（▼ Session N）をクリックすると、そのセッションの周回だけを畳めます（▶）。
         もう一度クリックで開きます。「すべて畳む」「すべて展開」で一括操作。畳んでも、区切り行に時間帯・周回数・ベスト・最高速が残ります
       ・右上の「◀ 設定を隠す」で、左の設定パネルを隠して結果を広く表示できます
       ・備考が列に収まらないときは、その行にマウスを乗せると全文が出ます
       ・画面下部の「ログ」の見出しをクリックで、ログ欄を畳めます（畳んでいる間は、見出しに最新のログ 1 行が出ます）
  6. ベストのマーク: ★ = 全セッション通しての最速, ※ = そのセッション内での最速
     ・「タイム順 (セッションごと)」にチェック: セッションごとに、周回をラップタイムの速い順に並べ、「1位」「2位」…を付けます
       （アウト・イン・無効な周回は後ろ）。全セッション表示のときは、区切り行の下でそれぞれ並べます
       対象は ラップタイム・各区間のタイム・最高速（1 周の中で出た最高の km/h）。セッション一覧にも最高速を表示します
       最高速は実際に出た速度なので、遅い周回や IN ラップも対象です。コントロールラインでの速度は前後の 2 周の両方に含まれるため、
       そこが最高速のときは 2 周に同じ値が付くことがあります
     OUT・無効・途中・未完の周回と、「遅い周回」(スピン・コースアウトなど) は、ベストの対象外です
     遅い周回 = 周回タイムがセッションの中央値の 1.25 倍 (画面の「遅い周回の倍率」) を超える周回、または
     どれかの区間がセッション内のその区間の中央値の 1.5 倍を超える周回。備考に理由を表示します
  6b. 「基準差」の列: 基準の周回とのラップタイムの差（秒。＋ = 基準より遅い）。基準の周回には「基準」と出ます。
     基準は初め全体のベスト（★）。周回表の行を右クリックして「この周回を基準にする」で変え、「基準を全体のベストに戻す」で戻します。
     列の見出しに今の基準（例: 基準差 (S2-L5)）を表示します。解析し直しても、同じ開始時刻の周回があれば基準のままです（保存はしません）
  7. 順序が崩れた周回（ラインの検出漏れ・逆走など）は、赤で「×」と理由を表示します。
     セクターラインの検出漏れだけなら、その区間タイムだけ空欄にして周回は有効のままです
  ※ 画面の設定の保存: 各画面のウィンドウの位置・大きさと、入力した設定（下記）は、閉じるときに保存し、次に開いたときに戻します。
     保存先は exe と同じフォルダの WintecTK2Converter.settings.json（書き込めない場合は %LOCALAPPDATA%\WintecTK2Converter\）。
     ・メイン画面: 出力先、出力形式（KMZ / KML / なし）、RMC の日付、高さ、走行アニメーション、補正する週数（tk2nmea.ini より優先）
     ・コース定義の作成: 種類（サーキット / ジムカーナ）、コース名、速度の下限、周回の所要時間倍率、セクター数、ラインの片側の長さ
     ・ラップ解析: 停止とみなす秒数、通過の最低速度、遅い周回の倍率、全セッション表示、一覧・周回表・ログの開閉、設定パネルの表示、
       最後に使ったコース定義（コース定義を指定せずに開いたときに、自動で読み込みます）
     ・比較再生: 速度、繰り返し、軌跡・名前・航空写真の表示、表示（全体 / 拡大）、表示幅
     ・ファイル選択で最後に開いたフォルダ（.tk2、走行ログ、コース定義、CSV）
     前回の位置が画面の外になる場合（モニターを外したときなど）は、位置を戻しません。設定ファイルを消すと、既定の状態に戻ります。
  8c. 周回の比較再生: 周回表で周回を選び（Ctrl / Shift で複数選択）、「▶ 選んだ周回を比較再生...」（または右クリック）を押すと、
      コース定義の上で、選んだ周回をコントロールラインの通過から同時に走らせて比較できます（ログが必要。OUT・未完・無効の周回は対象外、最大 10 周）。
      再生・一時停止、速度（0.1〜4 倍）、スライダーで位置の移動、繰り返し、軌跡・名前の表示切り替え。
      右の一覧に、各周回のラップ・そのときの速度・基準の周回との差（秒。＋ = 基準より遅れ）が出ます。基準は、既定でいちばん速い周回で、切り替えられます。
        差は「同じ所に基準の周回が着いた時刻」との差です。同じ所は、ラインの間ごとに走った距離の割合で決めます（周回によって走った距離が少し違っても、ラインの所で差がずれません）。
      「表示」を「基準の周回を中心に拡大」にすると、基準の周回の自車位置を中心に追いかけて拡大表示し、走行ラインの違いを見られます（鈴鹿のように広いコース向け）。
      拡大率は ＋／－ またはマウスホイールで変更（表示幅 20〜3000 m）。左下に縮尺を表示。全体表示でホイールを上に回すと拡大表示に切り替わります。
      「航空写真」をオンにすると、背景に国土地理院の航空写真（地理院タイル「全国最新写真（シームレス）」）を表示し、実際のコースの上で走行ラインを比べられます。
      インターネット接続が必要です。読み込んだ写真は %LOCALAPPDATA%\WintecTK2Converter\tiles\ に保存し、次回から使います。
      GPS の測位には数 m のずれがあるので、写真と少しずれて見えることがあります。
  8e. 距離ごとの比較: 周回表（走行一覧）で周回・走行を選び、「距離ごとに比較...」（または右クリック）を押すと、
      横軸 = スタート（コントロール）ラインからの距離で、上に速度、下に基準とのタイム差（＋ = 基準より遅れ）のグラフを出します。
      右へ上がる所で差がつき、下がる所で取り返しています。どこで差がついたか（サイドターン・スラローム・コーナー）を見る用です。
      ・基準は既定でいちばん速いもの。上の「基準」で切り替え
      ・グラフにマウスを乗せると、その距離での各走行の速度と差を右の一覧に出します
      ・ホイールで横方向に拡大・縮小、ドラッグで左右に動かす。「全体を表示」で戻す
      ・距離は、各ラインを通った時刻を中心線上のラインの位置に合わせ、ラインの間はその走行が走った距離の割合で割り振っています。
        ラインの所では正確、ラインの間は走行ラインの違いで少しずれることがあります（セクターを増やすと細かく合います）
  8d. 動画素材の書き出し: セッション一覧か周回表でセッションを選び、「動画素材を書き出す...」を押すと、
      速度計・G メーター・コース図・ラップ表・セクター表・文字データを描いた透明付きの動画（ProRes 4444 の .mov）を書き出します。
      形式は「QuickTime Animation」も選べます。劣化なしで、透明の多い素材では ProRes の 1/8 ほどの大きさになります。
      DaVinci Resolve などで走行動画の上のトラックに置き、スタート位置を合わせて使います（ツールに同期の機能はありません）。
      見た目は AviUtl の VSD for GPS（standard_l3 スキン）に合わせています。配置・大きさ・色はレイアウトの ini で変えられます
      （既定は exe と同じフォルダの overlay_default.ini。中の注釈を参照）。
      ・メーターの画像は VSD の standard.png を使います（同梱していません）。overlay_default.ini と同じフォルダに置くか、
        ini の image に場所を書いてください。見つからなければ代わりの円盤を描きます。
      ・差分（＋ = 遅れ）は走行中も更新します。基準は、その時点までに走り終えたセッション内のベスト（周回・区間それぞれ）。
      ・速度計の数字は、最高値が 140 km/h を超えるとき（鈴鹿など）は 20 km/h ごとにだけ書きます（ini の speedometer の wide）。
      ・G は加速度センサーが無いので、速度と向きの変化から計算します（gmeter の smooth で滑らかさを調整）。
      ・ジムカーナでは「範囲」を選べます。「走行ごと」（既定）は 1 本ずつ別のファイルにします（走行の前・後の秒数を付けて。
        ファイル名の末尾は _R1, _R2...）。コース外で待っている時間を書き出さずに済みます。「○本目だけ」「セッション全体」も選べます。
        保存先で選ぶのは 1 本目のファイル名で、ほかの走行は同じフォルダに並びます。ベストや差分はセッション全体で計算するので、
        別々のファイルでも、その時点までのベストとの比較になります。
        ジムカーナの素材は、右上が「Heat 番号」（Session ではなく走行の番号）で、ベストと履歴の行は出しません。
        セクター表はラップタイムの下（右寄せ）に置きます。ラップ解析の走行一覧も「Heat」列に番号だけを表示します
      ・ラップタイムの「Time」の左に、いま表示している周回の名前を出します（サーキット: Lap 3 / Out Lap / In Lap、
        ジムカーナ: Heat 2）。周回が終わった直後にタイムを残している間は、終わった周回の名前のままです
      ・サーキットのセッションは、最初にラインを通る前の発進（ピットを出る所。止まっていた所）から始まります。
      ・大きさ（1920x1080 など）、フレームレート、セッションの前後の余白（秒）を選べます。プレビューのスライダーで確認、
        「この時刻を PNG で保存...」で 1 枚だけ保存できます。
      ・ffmpeg が必要です（winget install Gyan.FFmpeg）。PATH や winget の入れ場所から自動で探します。
        無い場合は「透明 PNG 連番」で書き出せます。
      ・書き出しはおよそ実時間かかります（1920x1080・29.97fps で 20 分のセッションに 20 分前後）。
      ・「サブ動画も含める」にチェックすると、走行動画の時刻合わせで登録したサブ動画（ペダルなど。8e）を、
        レイアウトの [subvideo] の枠に入れて書き出します（表示の下。音声は入りません）。既定は OFF で、開くたびに OFF に戻ります
        （Resolve 側でサブを別に重ねるときは外したままにします）。PNG 連番でも ffmpeg が必要です。
        書き出す範囲にサブ動画が無ければ、サブなしで書き出します。
      ・「編集...」（レイアウトの行）で、表示のレイアウトエディタを開きます（下の「表示の編集」）。
  8e. 走行動画の時刻合わせ・切り出し: セッション一覧か周回表でセッションを選び、「走行動画の時刻合わせ・切り出し...」を押します。
      「開く...」で走行動画を選び、ログの時刻と合わせます（一度合わせれば、ログの付属情報「ログ名.log.json」に保存され、次からは一覧に出ます）。
      ・合わせ方: 右の一覧で周回（ジムカーナは走行）を 1 つ選び、動画をコマ送りして、その周回の開始（コントロールラインを通った瞬間）の
        コマを出して「このコマが選んだ周回の開始」を押します。一覧をダブルクリックすると、その周回の開始の所へ移動します。
      ・合っているかは、映像に重ねた表示（動画素材と同じ速度計・タイム・セクター表）と映像を見比べて確かめます。
        ずれていたら「表示を動画に対して動かす」のボタン（±1 秒・±0.1 秒・±1 コマ）で直せます。直した値もすぐ保存します。
      ・操作: スペース = 再生・一時停止、← → = 1 コマ戻す・進める。
      ・エンジンの回転数・アクセル（音声から）: 時刻を合わせたあと「音声を解析」を押すと、動画の音声からこのセッションの回転数と
        アクセルの ON / OFF を求めて「ログ名.rpm.json」（車の設定は「ログ名.log.json」）に保存し、確かめる図の画面を開きます（8 分の動画で数秒）。
        変速機・遠心クラッチの無い直結の 2 スト単気筒（レーシングカートの KT100 など）が前提です。回転数 = 音の基本周波数 × 60。
        直結なので 回転数 = 係数 × 速度。係数（rpm / (km/h)。スプロケットの歯数とタイヤの外径で決まる）は音から自動で求めます
        （20261107 の動画では 171.3 = 100 km/h で 17,130 rpm）。合わないときは図の画面で手で直して保存できます。
        図: 明るい線がエンジン音の倍音。水色 = 係数 × 速度 の倍音、赤 = 音から求めた回転数の倍音、下の帯 = アクセル（緑 ON / 灰 OFF）。
        アクセルは、音の「倍音らしさ」が、GPS で加速中と減速中の平均の中間より上なら ON です（踏み加減の細かい段階までは分かりません）。
        解析結果があると、動画素材の書き出し・切り出しの焼き込み・動画で比較の表示に、回転計（横棒と数字）とアクセル（縦棒 THR）が出ます。
        既定は加速度計と情報の上で、少し透けます（opacity）。位置・目盛り（max 16000 / yellow 13000 / red 15000 rpm）はレイアウトの ini の [tacho] 節で変えられます
        （節が無いレイアウトでも既定の位置に出ます。消すときは [tacho] に show = 0）。回転数は 係数 × メーターの速度 なので針と同じ動き。
        音の回転数が速度からの回転数より 8 % 以上高いと「SLIP」（後輪の空転・スライド）を出します。
      ・変速機付きの車（DC5 インテグラ・EK9 シビック・EF8 CR-X など。ジムカーナでもサーキットでも）: 「音声を解析」の左の「車」で
        車両のセット（例「DC5 インテグラ Type R (変速機付き)」）を選んでから解析します。
        速度に縛らずに、エンジン音の線を時間に沿ってたどって回転数を求めます（ギア・ブリッピング・空転があるため）。
        回転数 = 音の基本周波数 × 60 ÷ (気筒数 ÷ 2)。車内のマイクでは高い倍音が弱いので、低い倍音ほど重く見ます。アクセルは求めません。
        車両のセット = ギア比（1 速から、カンマ区切り）・最終減速比・タイヤ（215/45R17 の形。走っているときの 1 周は表記の 97 %、または 1 周 [m] を直接）・
        気筒数・回転計の目盛り（最高, 黄, 赤）のまとまりです。最初から入っているのは純正の値です。
          DC5 インテグラ Type R : 3.266, 2.130, 1.517, 1.212, 0.972, 0.780 / 4.764 / 215/45R17 / 9000, 7500, 8200
          EK9 シビック Type R   : 3.230, 2.105, 1.458, 1.107, 0.848 / 4.400 / 195/55R15 / 10000, 8000, 8400
          EF8 CR-X SiR          : 3.166, 2.052, 1.416, 1.103, 0.870 / 4.266 / 195/60R14 / 9000, 7500, 8000
        解析結果の画面の「車両」でセットを選ぶと欄の値がまとめて切り替わり、「保存」でこのログに使います。
        レース車両・ジムカーナ車両でファイナルやタイヤを変えているときは、欄を直して「セットに保存」します（同じ名前なら純正の値より優先。
        「名前」の欄に新しい名前を入れれば別のセットとして足せます）。セットは exe と同じフォルダの WintecTK2Converter.cars.json に保存し、ほかのログでも選べます。
        「セットを消す」で保存したセットを消します（最初から入っている車は純正の値に戻ります）。
        同じログで同じセットを選んで解析し直すと、解析結果の画面で直した値をそのまま使います。違うセットを選ぶと、そのセットの値に切り替えます。
        「使う一番上のギア」は解析のたびに音から自動で決めます（1 回目は縛らずに音の線をたどり、25 km/h 以上で加速中か速度がほぼ一定の所で
        使っているギアを数える。ジムカーナの 1・2 速だけの走行なら 2、サーキットなら 5 や 6）。決まった値は画面に入ります。
        画面で別の値に書き換えて「保存」すると、その値に固定します（自動に戻すには 0 を入れて保存）。
        加速中は、使うギアのどれかで速度から計算した回転数の −15 %〜+35 % の線だけをたどります（車内の低い騒音の線や、本当の音の半分の高さの線を
        拾うのを防ぐため）。雑音は前後 30 秒の中央値で引きます。
        解析する範囲は、このセッションの走っている所だけです（ジムカーナは動画に重なる走行の最初のスタートの 20 秒前〜最後の走行の 15 秒後。
        サーキットはピットを出る所（または最初のラインの 60 秒前）〜セッションの 60 秒後）。動画全体（待ち時間・パドック）は使いません。
        回転計には、音から求めた回転数をそのまま出します（ブリッピング・空転もそのまま見えます）。アクセルの縦棒の所にギアの数字を出します。
        ギアは 音の回転数 ÷ 速度 にいちばん近いギア（空転で上に出るぶんは軽く見る）を、前後 0.5 秒の多数決で決めます。どのギアからも
        40 % 以上離れているときや、2,000 rpm 未満（サイドターンなどでクラッチを切ってアイドル付近）のときは、
        4 秒以内に次に決まるギアを先に出します（サイドターン中は次の 1 速）。それも無ければ「-」。加速中に、そのギアで速度から計算した回転数より 8 % 以上高いと「SLIP」。
        図: 赤 = 音から求めた回転数、水色の点線 = 各ギアで速度から計算した回転数、下の帯 = ギア（緑 1 速、青 2 速、黄 3 速…）。
        上の説明の欄に、ギアごとの 計算の値 と 音の値（下位 10 % と中央）の違いが出ます。グリップしている下の端が計算と合っていれば、ギア比とタイヤは合っています。
      ・心拍（腕時計などの FIT ファイルから）: 「FIT を開く...」で、このセッションのドライバーが着けていた腕時計などの FIT ファイル
        （Polar・Garmin など。各社のアプリから書き出せます）を選びます。腕時計の時計は日付ごと狂っていることがあるので（Polar は
        スマホとの同期で時計を合わせ、GPS では合わせません）、FIT の時刻は使わず、このセッションの前後 10 分（セッションが FIT より短いときは、FIT が丸ごと入る長さまで広げます）の中で、FIT の速度とログの速度の
        形（相関）がいちばん合う所を探して、心拍の対応を「ログ名.log.json」に保存します（FIT はログのそばの heart フォルダにコピーし、表示のたびにそこから読みます）。腕時計の GPS は速度が鈍るので、大きさではなく形で比べます。
        比べるのは FIT のうちカートに乗って走っていた所だけで（乗る前・降りた後に立っている間は、カートをほかの人が走らせているので比べません）、
        その走った所がこのセッションに重なる所だけを探します。別のセッション・ログに無い別のカートの FIT を選ぶと、合い方が弱いと注意が出ます。
        腕時計を交代で使っていても、セッションごとにその人が着けていた FIT を選んでください（同じ FIT を 2 つのセッションに使うこともできます）。
        周回ごとに似た形が繰り返すので、1 周ずれた所も候補に出ます。「候補」で切り替えられます（揃い = 走った所を数分ごとに区切って合わせ直したとき、
        同じ所に揃った区間の数。多いほど確か）。合い方が弱いと注意が出るので、映像と見比べて確かめてください。位置・速度は時刻を合わせるためだけに使い、表示には使いません。
        保存すると、動画素材の書き出し・切り出しの焼き込み・動画で比較の表示で、右上のドライバー名の右にハートと心拍数（3 桁）が出ます。
        ハートは心拍に合わせて明滅します（拍の瞬間に明るく、次の拍までに暗くなる）。FIT が無いセッションでは何も出ません。
        ずれは「心拍を動画に対して動かす」のボタン（±1 秒・±0.1 秒）で直せます。「自動に戻す」で速度から求めた値に戻ります。「外す」で表示しなくなります。
        FIT はセッションごとに持ちます（ドライバーごとに別の腕時計でもよい）。合わせたセッションにだけ出します（交代で腕時計を渡すため）。
        FIT に速度が無いときは FIT の時刻のまま保存します（その時刻がセッションに重ならなければ保存しません）。
        色・明滅の速さはレイアウトの ini の [heart] 節で変えられます（消すときは show = 0）。
      ・速度のグラフ（任意）: 「速度のグラフ」にチェックを入れると、右下のセクター表示の上に、距離ごとの速度のグラフが出ます。
        チェックは動画素材の書き出し・走行動画の時刻合わせ（焼き込みの切り出しにも効きます）・動画で比較の 3 つの画面にあり、設定は共通です（どこかで変えると、開いているほかの画面にもすぐ反映します）。
        その時点のベストの周回が薄い面と線で背景に、走行中の周回が線で伸びていきます（ラインを通ると消えて描き直します）。
        ベストが更新されると背景もその周回に替わります。アウトラップ・IN ラップなどは線を描かず背景だけです。
        面の濃さ（fill）・下敷きの濃さ（back）・高さ・色などは [graph] 節で変えられます。右上のラップタイムには重ならないよう高さを自動で縮めます。
      ・セッション番号: ラップタイムの先頭の行に「Session 3」のように出します（[laptime] の session = 0 で消せます。ジムカーナは左の Heat 名があるので出しません）。
        右上の [session] の行はドライバー名と心拍だけです。
      ・表示の背景（任意）: ドライバー・心拍・コース図・ラップタイム・セクタータイムの下に、それぞれ別に薄い背景を敷けます（明るい路面でも読みやすく）。
        「表示の編集...」（レイアウトエディタ）で要素を選び、「背景」にチェックを入れます。色は「背景の色」（#RRGGBB / #AARRGGBB）、濃さは「背景の濃さ」（0〜1、既定 0.12 = グラフの背景と同じ）。
        レイアウトの ini では [session] [map] [laptime] [sector] 節の background = 1 / panel / panelopacity / panelpad（余白）です。
      ・切り出し: 一覧で周回を選び（Ctrl / Shift で複数）、前後の秒数を決めて「切り出す」を押すと、元の動画と同じフォルダに
        「元の名前_S6_L3.mp4」のように 1 周ずつ保存します（H.264 + AAC、再エンコードなのでコマ単位で正確。音声は付けないこともできます）。
        「連続している周回を1つに結合」に入れると、続いている周回（例: L3・L4・L5）を 1 本にまとめ
        （「元の名前_S6_L3-L5.mp4」）、間が空いた所で別の動画に分けます。前後の余白はまとめた範囲の最初と最後にだけ付きます。
        切り出した動画も時刻合わせ済みとして登録するので、比較にそのまま使えます。
      ・「速度・タイム・セクターを焼き込む」にチェックすると、動画素材の書き出しと同じ表示（同じレイアウトの設定）を映像に重ねて
        切り出します（「元の名前_S6_L3_overlay.mp4」）。表示はその周回（走行）を中心にしたもので、映像と同じ大きさ・コマ数で描きます。
        表示は後から消せません。書き出しは表示を描くぶん遅くなります（1080p60 で 4 秒の範囲に約 5 秒）。
        焼き込んだ動画は「動画で比較」では使いません（表示が二重になるので、元の動画か焼き込みなしの切り出しを使います）。
      ・どの形式の動画でも、ffmpeg が読めれば使えます（AV1・HEVC など）。ffmpeg は「動画素材を書き出す...」の画面で指定したものを使います。
      ・サブ動画（ペダルなど別のカメラ）: 走行動画の時刻を合わせたあと「サブ動画を開く...」で選ぶと、走行動画に小さく重ねます
        （1 本まで。解像度・fps は何でも可。再生ではサブの音声は使いません）。はじめは「2 本が同時に録り始めた」として重ねます。
        ・「音声で合わせる」: メインの今の位置の前後 60 秒の音声を、サブの今のずれの前後 5 分の中で探し、候補を 3 つまで出します
          （エンジン音などの大きさの変化の形で比べます。際立ち 10 以上ならまず確か、5 未満は疑わしい）。
          合わないときは、エンジンの音がはっきりしている所（走行中）に動かしてからもう一度押します。もう一度押すと取りやめます。
        ・「ずれ」は数値で直すか、±1 秒・±0.1 秒・±1 コマのボタンで直します。走行動画の時刻を直すと、サブもずれを保ったまま動きます。
        ・トリミング（上・下・左・右の %。ホイールでも変えられます）で、焼き込みの日付などを隠せます。縦横比は保ったまま枠に収めます。
        ・ずれ・トリミングは変えるとすぐ「ログ名.log.json」に保存します（サブ動画ごと）。枠の位置・大きさはレイアウトの [subvideo] です。
        ・切り出しで「焼き込む」と「重ねる」が両方 ON のときは、サブ動画も焼き込みます（「(表示・サブ動画入り)」）。
        ・「外す」で登録を外します（動画のファイルは消しません）。
      ・表示の編集（「表示の編集...」。動画素材の書き出し・動画で比較にもあります）: 今のコマの上で、表示の要素
        （速度計・G メーター・回転計・コース図・ラップタイム・セクター・情報・サブ動画など）の ON / OFF と位置・大きさを直します。
        プレビューの要素をクリックで選び、ドラッグで動かします。矢印キーで 1 ずつ（Shift で 10）、Ctrl+Z で元に戻します。
        基準の角を変えても見た目の位置は変わりません。「この要素を既定に」「すべて既定に」で既定の値に戻せます。
        変えた内容は呼び出した画面にすぐ反映します。保存は別のファイルにします（最初の保存は「名前を付けて保存」。既定の名前は
        overlay_user.ini）。overlay_default.ini は書き換えません。保存したレイアウトは次から各画面で使います。
        サブ動画の枠を選ぶと、トリミングもここで直せます。
  8f. 動画で比較: 周回表で 2 つの周回（ジムカーナは走行）を Ctrl を押しながら選び、「▶ 動画で比較...」を押すと、
      2 つの動画を並べて同時に再生します（どちらも時刻合わせした動画が必要。切り出した動画があればそちらを使います）。
      ・両方とも、周回の開始（ラインの通過）を 0 秒にして同時に進みます。前後に 3 秒の余白。違うセッション・違う日のログの周回でも比べられます。
      ・「揃える位置」でセクターの開始（S2 の開始など）を選ぶと、両方がそのセクターに入った瞬間を 0 秒にして再生します。
        セクターごとの違いを細かく比べるときに使います。⏮ と「繰り返す」もそのセクターの 3 秒前から。地図も同じ位置で揃え、
        地図のタイム差は揃えた位置で 0.00 秒、そこからの差になります。
      ・それぞれの映像に、動画素材と同じ表示（速度計・ラップタイムと差・セクター表など）を重ねます（チェックで消せます）。
        表示のレイアウトは「動画素材を書き出す...」で最後に選んだものです。「表示の編集...」で直せます（A の映像で確認し、両方に反映）。
      ・サブ動画（8e で登録したもの）があれば、それぞれの映像に重ねます（「サブ動画」のチェックで消せます。音声は出しません）。
      ・音声は「両方・A だけ・B だけ・なし・左右に分ける」を切り替えられます（キーの 3 / 1 / 2 / 0 / 4 でも）。
        「左右に分ける」は、A の音をモノラルにして左のスピーカー、B の音をモノラルにして右のスピーカーから出します。音声が出るのは 1 × のときだけです。
      ・「地図 (航空写真) を開く」で、比較再生の画面（2 台の位置を航空写真の上で比べる）が開き、この画面の再生と一緒に動きます
        （はじめに自動で開きます）。
      ・並べ方は左右・上下。速度は 0.1〜2 ×。スペース = 再生・一時停止、← → = コマ送り。
      ・「並べて配置」: この画面を上（高さの約 63 %）に大きく、ラップ・セクタータイムを左下（幅の 6 割）、地図を右下に並べます
        （この画面があるモニターに合わせます）。どの画面もクリックすれば手前に出せます。
        並べたあと手で位置・大きさを直したら、「並べて配置」ボタンを右クリックして「現在のレイアウトを保存」を選ぶと、
        次からは（開いたときも）その並べ方で並べます。モニターの作業領域に対する割合で覚えます。
        「初期レイアウトを保存」を選ぶと、保存した並べ方を消して初めの並べ方に戻します。
        並べた位置は、それぞれの画面（ラップ解析・地図・この画面）の位置・大きさとしては保存しません。
  8b. 「CSV を開く...」: 保存したラップ CSV をそのまま表示します（読み取り専用。ログやコース定義は不要）。
      セッション一覧・周回表・★※のマークを、保存したときの表で見られます。ドライバー名は画面で直して、CSV に保存し直せます。
      ログがないので、分割・結合や再解析はできません（できるのは、ログとコース定義から「解析する」を押したときだけ）。
  8. 「CSV に保存...」: Session, Driver, Lap, Type (OUT/LAP/IN/PARTIAL/INCOMPLETE), 開始時刻, 各区間, ラップ,
     区間ごとの最高速度, 備考を全セッション続けて保存（Excel で開けます）
  GPS は 1 秒間隔なので、通過時刻は 0.1〜0.2 秒程度の誤差があります。ラップ間の比較には十分ですが、公式計時の代わりにはなりません。
■ ビルド（ソース更新時に1回）
  build.bat をダブルクリックすると、同じフォルダに tk2nmea.exe ができます。
  Windows に標準で入っている .NET Framework 4.5 以降の C# コンパイラを使うので、
  Visual Studio などのインストールは不要です。

■ 使い方
  1. .tk2 ファイル（複数可）またはフォルダを tk2nmea.exe にドラッグ＆ドロップ
  2. 記録の時間範囲と「停止区間（60秒以上記録なし）」が表示されます
  3. 前後をカットしたい場合は開始時刻・終了時刻を入力（例 08:05:00）
     Enter だけ押すとカットしません
  4. 同じフォルダに次のファイルができます（名前はカット後の開始日時）
       YYYYMMDD_HHMMSS.nmea  … NMEA
       YYYYMMDD_HHMMSS.kmz   … Google Earth Pro 用

  カット位置の決め方の例:
    まずカットせずに変換 → KMZ を Google Earth で開き、Km_Posts や軌跡の時刻を見て
    必要な区間の時刻を確認 → もう一度ドロップして時刻を入力

■ KMZ（Google Earth Pro 用）の中身
  ・スタート（緑）/ ゴール（赤）の目印
  ・走行軌跡 (時間再生) : 時間スライダーで走行位置のアイコンが動きます
  ・Speed_Track(Km)     : 速度で色分けした線。既定は 5km/h 刻み
                          紫(0) → 青(20) → 水色(40) → 緑(60) → 黄(80) → 橙(100) → 赤(120以上) の間を
                          なめらかに補間した色（speedstep=20 にすると TimeMachineX と同じ 7 色）
  ・Km_Posts            : スタートから 1km ごとの目印（通過時刻・経過時間・速度付き）
                          シンボル・色・大きさは tk2nmea.ini で変更できます
  ・画面左下に速度の凡例
  ・走行アニメーション（ツアー）: 「場所」パネルの「走行アニメーション」をダブルクリックで再生。
          カメラが車を追いかけ、走った所だけ Speed_Track の線と Km ポストが現れて残ります。
          動画にするには「ツール → ムービーメーカー」で、このツアーを選んで録画します。
          ツアーを作るとき、Speed_Track・Km ポストには通過時刻が付くため、普段の表示でも
          画面上部の時間スライダーで表示範囲を変えられます（全部表示するときはスライダーを全範囲に）。
  ・高さ: 既定では GPS で記録した高度で線を描きます（橋や高架道路の上に線が乗ります）。
          Google Earth の地形には橋や高架が含まれないため、「地表に沿わせる」表示だと
          橋の上では海面に線が描かれてしまうためです。
          GPS の高さは誤差があり、実際より 10～20m ほど高めに出ることがあります。
          線が道路から浮いて見える場合は tk2nmea.ini の altoffset をマイナスにしてください。
  速度・距離・Km ポストの計算は TimeMachineX と同じ方式です。

■ 設定ファイル tk2nmea.ini（exe と同じフォルダ）
  メモ帳で開いて書き換え、保存すると次のドロップから反映されます。
    kmicon    Km ポストのシンボル: pin / flag / star / circle / square / diamond /
              triangle / target / donut / dot / paddle、画像の URL、または png ファイル
    kmcolor   シンボルとラベルの色: yellow / orange / red / white など、または #RRGGBB
    kmscale   シンボルの大きさ（1 = 標準）
    kmlabel   「5 Km」の文字の大きさ（0 で非表示）
    speedstep Speed_Track の色分けの幅 [km/h]
    speedmax  この速度以上を最高色（赤）にする [km/h]
    altitude  gps = GPS 高度で表示 / ground = 地表に沿わせる
    altoffset GPS 高度の補正値 [m]（例 -10）
    groundoffset altitude=ground のとき、線・マーカー・カメラを地表から浮かせる高さ [m]（0 = 浮かせない）
    altsmooth GPS 高度の移動平均の幅 [秒]
    extrude   1 = 線から地面まで幕を下ろす
    tour        1 = 走行アニメーション（ツアー）を作る / 0 = 作らない
    tourspeed   再生の倍速（10 なら 1 時間の走行を 6 分で再生）
    tourstep    カメラ位置の間隔 [秒]
    tourrange   カメラから車までの距離 [m]
    tourtilt    カメラの傾き [度]（0 = 真上, 90 = 水平）
    tourheading follow = 進行方向を向く / north = 北が上
    trackline   1 = 走行軌跡自身の線を表示（単色。時間に合わせて滑らかに伸びる。Speed_Track は非表示）
    trackcolor  trackline の線の色（名前 / #RRGGBB）
    trackwidth  trackline の線の太さ
    carname     自車マーカーの下に出すラベル（車種名など。空なら出さない）
    carlabel    ラベルの大きさ
    tourseg     軌跡を伸ばす刻みの分割数（2 = 0.5 秒刻み, 3 = 1/3 秒刻み, 1 = 分割しない）
    tourlead    軌跡の先端位置の補正 [秒]（0 = 車が通過した点まで。+ で先行、- で後退）
    tourheadwin 進行方向を求める範囲 [秒]（大きいほどカーブでカメラが振られにくい）
    tourheadtau カメラの向きの追従の遅れ [秒]（0 = すぐ向く。大きいほどゆっくり追従）
    googleearth  kmz / kml / none
    localdate 0 = NMEA の日付を UTC / 1 = 日本時間
  シンボルの見本: kmicon_samples.kmz を Google Earth で開くと、シンボル × 色を並べて比較できます。

■ 補正内容
  ロガーが GPS 週番号ロールオーバーで 1024 週（7168日）前の日付を記録しているため、
  2019-04-07 より前の日付には自動で 1024 週を加算します。時刻はそのままです。
  NMEA のチェックサムは出力時に正しく計算されます。

■ NMEA の日付について
  NMEA の $GPRMC の日付は規格上 UTC です。既定では UTC 日付で出力します
  （例: 日本時間 2026-09-26 07:08 は UTC 2026-09-25 22:08 → "250926"）。
  日本時間の日付（"260926"）で出したい場合は tk2nmea_日本時間日付.bat にドロップするか、
  -localdate を付けてください。

■ コマンドラインオプション
  -start T    この時刻より前をカット（08:05:00 / 08:05 / 2026-09-26 08:05:00）
  -end T      この時刻より後をカット
  -localdate  RMC の日付を現地日付（ヘッダのタイムゾーン）で出力
  -weeks N    補正週数を手動指定（0 で補正なし、既定は自動）
  -o DIR      出力先フォルダ
  -kml        KMZ ではなく KML で出力（凡例画像なし）
  -nokml      Google Earth 用ファイルを出力しない（NMEA のみ）
  -nopause    時刻の問い合わせと終了時の Enter 待ちをしない
  -kmicon X / -kmcolor C / -kmscale S / -kmlabel S / -speedstep N / -speedmax N
  -altitude gps|ground / -altoffset m / -groundoffset m / -altsmooth 秒 / -extrude 0|1
  -tour 0|1 / -tourspeed 倍 / -tourstep 秒 / -tourrange m / -tourtilt 度 / -tourheading follow|north / -trackline 0|1 / -trackcolor C / -trackwidth N / -carname 名前 / -carlabel S / -tourseg N / -tourlead 秒 / -tourheadwin 秒 / -tourheadtau 秒
              tk2nmea.ini と同じ設定（こちらが優先）

  例: tk2nmea.exe -start 07:30 -end 08:30 D:\GPS\20070210_070806.tk2
