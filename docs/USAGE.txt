tk2nmea (C#版) - Wintec TK2 → NMEA / KMZ 変換ツール（GPS週番号ロールオーバー補正付き）

■ WPF 版（画面付き: WintecTK2Converter.exe）
  build_gui.bat をダブルクリックすると gui\publish\WintecTK2Converter.exe ができます。
  （ビルドに .NET SDK 10、実行に .NET 10 デスクトップ ランタイムが必要です）
  1. 起動して .tk2 ファイル（複数可）またはフォルダをウィンドウへドラッグ＆ドロップ
     （「ファイルを追加...」「フォルダを追加...」ボタン、exe へのドロップでも追加できます）
  2. 一覧で選んだファイルの記録範囲と停止区間（60 秒以上記録なし）が左下に出ます
  3. 前後をカットしたいファイルは「開始カット」「終了カット」欄に現地時刻を入力（例 08:05:00）
     空欄ならカットしません。ファイルごとに別々に指定できます
  4. 右側で出力先・出力形式（KMZ / KML / NMEA のみ）・RMC の日付（日本時間にするか）・
     高さの表示・ツアーの有無・補正週数を選び、「変換する」を押す
  5. 結果は下のログ欄に出ます。「出力フォルダを開く」で出力先を開けます
  画面の初期値は tk2nmea.ini の内容です。画面にない細かい設定（Km ポスト、速度の色分け、
  ツアーのカメラなど）は、exe と同じフォルダの tk2nmea.ini で変更します。
  以下の「使い方」はコンソール版（tk2nmea.exe）の説明です。

■ コース定義の作成（WPF 版の「コース定義を作成...」）
  サーキット（周回コース）を走ったログから、コースの中心線・コントロールライン・セクターラインを作ります。
  今後のラップ・セクタータイム計測や、Google Earth での確認に使うファイルです。
  1. 「コース定義を作成...」を押す（メイン画面に .tk2 が並んでいれば最初から入ります）
     走行ログ（.tk2 / .nmea、複数可）を追加。周回が多いほど精度が上がります
     exe に「-course ファイル...」を付けて起動しても、この画面が開きます
  2. 「解析する」: 周回を重ね合わせて平均化し、中心線を求めます
       ・速度の下限（既定 18 km/h）より遅い点（ピット・停止・低速でばらつく所）は使いません
       ・周回ごとに所要時間・欠測を調べ、中央値の 1.2 倍を超える周回（ピットイン等）を除きます
       ・点そのものを使うので、1 秒間隔でもカーブを切り込みません
  3. 右のプレビューで確認（赤=中心線, 青=採用した周回, 橙=除外した周回, 矢印=進行方向）
  4. コントロールライン（スタート/ゴール）とセクターラインの位置を調整
     自動では、コントロールラインを停止・低速の点が多い所（ピット付近）に、セクターを周長の等分位置に置きます
     一覧で選んだライン 1 本だけを、スライダー・数値入力・±1m / ±5m ボタンで前後に動かせます（選んだラインは青で表示）
     「自動位置に戻す」で選んだラインを既定の位置へ、「等間隔に配置し直す」でセクター数を変えて全体を置き直します
  5. 「Google Earth で重ねて確認」: 中心線・ライン・元データを KML で開きます
     GPS の位置は実際より数 m ずれることがあるので、衛星写真と見比べて確認してください
  6. 「コース定義を保存...」: *.course.json（コース定義）と同名の .kml を保存します
  コース定義ファイル（JSON）: コース名, 周長, 回転方向, 中心線（約 2m ごとの緯度経度）, ゲート（コントロールライン
  とセクター。両端の緯度経度）, 解析の統計（採用周回数・ばらつき）, 元ログ名。「保存済みのコース定義を開く...」で読み込めます

■ ラップ・セクタータイム（WPF 版の「ラップ解析...」）
  コース定義（コントロールライン + セクターライン）と走行ログから、ラップタイムとセクタータイムを計算します。
  コース定義の作成画面の「このコースでラップ解析...」からも開けます。
  exe に「-lap コース定義.course.json ログ...」を付けて起動しても、この画面が開きます。
  1. コース定義 (*.course.json) を開き、走行ログ (.tk2 / .nmea) を追加して「解析する」
  2. 区間: S1 = コントロール → Sector1, S2 = Sector1 → Sector2, ... 最後の区間はコントロールラインで終わります
     通過時刻は、各点の間の線分とラインの交点を求め、距離の比で補間します（逆向きの通過・低速でのふらつきは無視）
  3. アウトラップ: 最初に通ったラインから計測します。Sector1 から始まれば S1 は空欄で、ラップタイムは出さず（OUT）、
     ベストの対象にもなりません。停止からの発進でコントロールラインから始まる周回も OUT です
  4. ピットイン: 一定時間（既定 30 秒）以上止まっていたら、そこでセッションを分けます（ドライバー交代など）
     ロガーが止まっている間は記録しない場合も、停止として扱います
       ・コントロールライン通過後に止まった場合: 通過した周回が IN ラップ
       ・コントロールラインに着く前に止まった場合: その周回は「未完」の IN（S1〜 は残ります）
     コントロールラインは、止まる位置（ピット）より手前に置いてください。コース定義の自動配置は停止位置の手前です
  4b. 停止の判定とセッションが食い違うときは、周回表を右クリックして手動で直せます
     ・周回の行 → 「この周回の前でセッションを分割」（止まっていない場所でも分けられます。コントロールラインから始まる周回の前で分けると、前のセッションの最後の周回は最後まで計測されて IN ラップになり、
       分けたあとの最初の周回は OUT にならず、その周回のセクターも計測されます）
     ・セッションの行（区切り行）または周回の行 → 「前のセッションと結合」（停止の判定で分かれたセッションをつなげます。
       停止はなかったものとして、前のラインの通過（例: コントロールライン）から計測を続けます。停止の時間はその区間に入るので、
       その周回は「結合: 停止を含む周回」と注記され、ベストの対象外になります。手動で分けたところに使うと、その分割が取り消されます）
     ・「このログの分割・結合をすべて取り消す」
     編集すると自動で再解析されます。編集はログごとに保存され、「停止とみなす秒数」を変えても保たれます。
     保存先は、ログファイルのそばの「ログ名.sessions.json」（書き込めない場合は %LOCALAPPDATA%\WintecTK2Converter\sessions\）。
  5. セッションごとにドライバー名を入力できます（入力すると自動で保存され、次に同じログを解析したときに復元されます）
     保存先は、ログファイルのそばの「ログ名.drivers.json」（書き込めない場合は %LOCALAPPDATA%\WintecTK2Converter\drivers\）。
     セッションの時間範囲で対応づけるので、「停止とみなす秒数」を変えてセッションの分かれ方が変わっても引き継がれます。名前を消すと保存も消えます
     「全セッションを続けて表示する」で、セッションごとの区切り行つきで一覧できます
     表示を広く使うための折りたたみ:
       ・「セッション一覧」「周回表」の見出し左の ⌃ で、それぞれ畳めます（畳むと、もう一方が広がります）
       ・全セッション表示では、区切り行（▼ Session N）をクリックすると、そのセッションの周回だけを畳めます（▶）。
         もう一度クリックで開きます。「すべて畳む」「すべて展開」で一括操作。畳んでも、区切り行に時間帯・周回数・ベスト・最高速が残ります
       ・右上の「◀ 設定を隠す」で、左の設定パネルを隠して結果を広く表示できます
       ・備考が列に収まらないときは、その行にマウスを乗せると全文が出ます
       ・画面下部の「ログ」の見出しをクリックで、ログ欄を畳めます（畳んでいる間は、見出しに最新のログ 1 行が出ます）
  6. ベストのマーク: ★ = 全セッション通しての最速, ※ = そのセッション内での最速
       対象は ラップタイム・各区間のタイム・最高速（1 周の中で出た最高の km/h）。セッション一覧にも最高速を表示します
       最高速は実際に出た速度なので、遅い周回や IN ラップも対象です。コントロールラインでの速度は前後の 2 周の両方に含まれるため、
       そこが最高速のときは 2 周に同じ値が付くことがあります
     OUT・無効・途中・未完の周回と、「遅い周回」(スピン・コースアウトなど) は、ベストの対象外です
     遅い周回 = 周回タイムがセッションの中央値の 1.25 倍 (画面の「遅い周回の倍率」) を超える周回、または
     どれかの区間がセッション内のその区間の中央値の 1.5 倍を超える周回。備考に理由を表示します
  7. 順序が崩れた周回（ラインの検出漏れ・逆走など）は、赤で「×」と理由を表示します。
     セクターラインの検出漏れだけなら、その区間タイムだけ空欄にして周回は有効のままです
  ※ 画面の設定の保存: 各画面のウィンドウの位置・大きさと、入力した設定（下記）は、閉じるときに保存し、次に開いたときに戻します。
     保存先は exe と同じフォルダの WintecTK2Converter.settings.json（書き込めない場合は %LOCALAPPDATA%\WintecTK2Converter\）。
     ・メイン画面: 出力先、出力形式（KMZ / KML / なし）、RMC の日付、高さ、走行アニメーション、補正する週数（tk2nmea.ini より優先）
     ・コース定義の作成: コース名、速度の下限、周回の所要時間倍率、セクター数、ラインの片側の長さ
     ・ラップ解析: 停止とみなす秒数、通過の最低速度、遅い周回の倍率、全セッション表示、一覧・周回表・ログの開閉、設定パネルの表示、
       最後に使ったコース定義（コース定義を指定せずに開いたときに、自動で読み込みます）
     ・比較再生: 速度、繰り返し、軌跡・名前・航空写真の表示、表示（全体 / 拡大）、表示幅
     ・ファイル選択で最後に開いたフォルダ（.tk2、走行ログ、コース定義、CSV）
     前回の位置が画面の外になる場合（モニターを外したときなど）は、位置を戻しません。設定ファイルを消すと、既定の状態に戻ります。
  8c. 周回の比較再生: 周回表で周回を選び（Ctrl / Shift で複数選択）、「▶ 選んだ周回を比較再生...」（または右クリック）を押すと、
      コース定義の上で、選んだ周回をコントロールラインの通過から同時に走らせて比較できます（ログが必要。OUT・未完・無効の周回は対象外、最大 10 周）。
      再生・一時停止、速度（0.1〜4 倍）、スライダーで位置の移動、繰り返し、軌跡・名前の表示切り替え。
      右の一覧に、各周回のラップ・そのときの速度・基準の周回との差（秒。＋ = 基準より遅れ）が出ます。基準は、既定でいちばん速い周回で、切り替えられます。
      「表示」を「基準の周回を中心に拡大」にすると、基準の周回の自車位置を中心に追いかけて拡大表示し、走行ラインの違いを見られます（鈴鹿のように広いコース向け）。
      拡大率は ＋／－ またはマウスホイールで変更（表示幅 20〜3000 m）。左下に縮尺を表示。全体表示でホイールを上に回すと拡大表示に切り替わります。
      「航空写真」をオンにすると、背景に国土地理院の航空写真（地理院タイル「全国最新写真（シームレス）」）を表示し、実際のコースの上で走行ラインを比べられます。
      インターネット接続が必要です。読み込んだ写真は %LOCALAPPDATA%\WintecTK2Converter\tiles\ に保存し、次回から使います。
      GPS の測位には数 m のずれがあるので、写真と少しずれて見えることがあります。
  8b. 「CSV を開く...」: 保存したラップ CSV をそのまま表示します（読み取り専用。ログやコース定義は不要）。
      セッション一覧・周回表・★※のマークを、保存したときの表で見られます。ドライバー名は画面で直して、CSV に保存し直せます。
      ログがないので、分割・結合や再解析はできません（できるのは、ログとコース定義から「解析する」を押したときだけ）。
  8. 「CSV に保存...」: Session, Driver, Lap, Type (OUT/LAP/IN/PARTIAL/INCOMPLETE), 開始時刻, 各区間, ラップ,
     区間ごとの最高速度, 備考を全セッション続けて保存（Excel で開けます）
  GPS は 1 秒間隔なので、通過時刻は 0.1〜0.2 秒程度の誤差があります。ラップ間の比較には十分ですが、公式計時の代わりにはなりません。
■ ビルド（ソース更新時に1回）
  build.bat をダブルクリックすると、同じフォルダに tk2nmea.exe ができます。
  Windows に標準で入っている .NET Framework 4.5 以降の C# コンパイラを使うので、
  Visual Studio などのインストールは不要です。

■ 使い方
  1. .tk2 ファイル（複数可）またはフォルダを tk2nmea.exe にドラッグ＆ドロップ
  2. 記録の時間範囲と「停止区間（60秒以上記録なし）」が表示されます
  3. 前後をカットしたい場合は開始時刻・終了時刻を入力（例 08:05:00）
     Enter だけ押すとカットしません
  4. 同じフォルダに次のファイルができます（名前はカット後の開始日時）
       YYYYMMDD_HHMMSS.nmea  … NMEA
       YYYYMMDD_HHMMSS.kmz   … Google Earth Pro 用

  カット位置の決め方の例:
    まずカットせずに変換 → KMZ を Google Earth で開き、Km_Posts や軌跡の時刻を見て
    必要な区間の時刻を確認 → もう一度ドロップして時刻を入力

■ KMZ（Google Earth Pro 用）の中身
  ・スタート（緑）/ ゴール（赤）の目印
  ・走行軌跡 (時間再生) : 時間スライダーで走行位置のアイコンが動きます
  ・Speed_Track(Km)     : 速度で色分けした線。既定は 5km/h 刻み
                          紫(0) → 青(20) → 水色(40) → 緑(60) → 黄(80) → 橙(100) → 赤(120以上) の間を
                          なめらかに補間した色（speedstep=20 にすると TimeMachineX と同じ 7 色）
  ・Km_Posts            : スタートから 1km ごとの目印（通過時刻・経過時間・速度付き）
                          シンボル・色・大きさは tk2nmea.ini で変更できます
  ・画面左下に速度の凡例
  ・走行アニメーション（ツアー）: 「場所」パネルの「走行アニメーション」をダブルクリックで再生。
          カメラが車を追いかけ、走った所だけ Speed_Track の線と Km ポストが現れて残ります。
          動画にするには「ツール → ムービーメーカー」で、このツアーを選んで録画します。
          ツアーを作るとき、Speed_Track・Km ポストには通過時刻が付くため、普段の表示でも
          画面上部の時間スライダーで表示範囲を変えられます（全部表示するときはスライダーを全範囲に）。
  ・高さ: 既定では GPS で記録した高度で線を描きます（橋や高架道路の上に線が乗ります）。
          Google Earth の地形には橋や高架が含まれないため、「地表に沿わせる」表示だと
          橋の上では海面に線が描かれてしまうためです。
          GPS の高さは誤差があり、実際より 10～20m ほど高めに出ることがあります。
          線が道路から浮いて見える場合は tk2nmea.ini の altoffset をマイナスにしてください。
  速度・距離・Km ポストの計算は TimeMachineX と同じ方式です。

■ 設定ファイル tk2nmea.ini（exe と同じフォルダ）
  メモ帳で開いて書き換え、保存すると次のドロップから反映されます。
    kmicon    Km ポストのシンボル: pin / flag / star / circle / square / diamond /
              triangle / target / donut / dot / paddle、画像の URL、または png ファイル
    kmcolor   シンボルとラベルの色: yellow / orange / red / white など、または #RRGGBB
    kmscale   シンボルの大きさ（1 = 標準）
    kmlabel   「5 Km」の文字の大きさ（0 で非表示）
    speedstep Speed_Track の色分けの幅 [km/h]
    speedmax  この速度以上を最高色（赤）にする [km/h]
    altitude  gps = GPS 高度で表示 / ground = 地表に沿わせる
    altoffset GPS 高度の補正値 [m]（例 -10）
    groundoffset altitude=ground のとき、線・マーカー・カメラを地表から浮かせる高さ [m]（0 = 浮かせない）
    altsmooth GPS 高度の移動平均の幅 [秒]
    extrude   1 = 線から地面まで幕を下ろす
    tour        1 = 走行アニメーション（ツアー）を作る / 0 = 作らない
    tourspeed   再生の倍速（10 なら 1 時間の走行を 6 分で再生）
    tourstep    カメラ位置の間隔 [秒]
    tourrange   カメラから車までの距離 [m]
    tourtilt    カメラの傾き [度]（0 = 真上, 90 = 水平）
    tourheading follow = 進行方向を向く / north = 北が上
    trackline   1 = 走行軌跡自身の線を表示（単色。時間に合わせて滑らかに伸びる。Speed_Track は非表示）
    trackcolor  trackline の線の色（名前 / #RRGGBB）
    trackwidth  trackline の線の太さ
    carname     自車マーカーの下に出すラベル（車種名など。空なら出さない）
    carlabel    ラベルの大きさ
    tourseg     軌跡を伸ばす刻みの分割数（2 = 0.5 秒刻み, 3 = 1/3 秒刻み, 1 = 分割しない）
    tourlead    軌跡の先端位置の補正 [秒]（0 = 車が通過した点まで。+ で先行、- で後退）
    tourheadwin 進行方向を求める範囲 [秒]（大きいほどカーブでカメラが振られにくい）
    tourheadtau カメラの向きの追従の遅れ [秒]（0 = すぐ向く。大きいほどゆっくり追従）
    googleearth  kmz / kml / none
    localdate 0 = NMEA の日付を UTC / 1 = 日本時間
  シンボルの見本: kmicon_samples.kmz を Google Earth で開くと、シンボル × 色を並べて比較できます。

■ 補正内容
  ロガーが GPS 週番号ロールオーバーで 1024 週（7168日）前の日付を記録しているため、
  2019-04-07 より前の日付には自動で 1024 週を加算します。時刻はそのままです。
  NMEA のチェックサムは出力時に正しく計算されます。

■ NMEA の日付について
  NMEA の $GPRMC の日付は規格上 UTC です。既定では UTC 日付で出力します
  （例: 日本時間 2026-09-26 07:08 は UTC 2026-09-25 22:08 → "250926"）。
  日本時間の日付（"260926"）で出したい場合は tk2nmea_日本時間日付.bat にドロップするか、
  -localdate を付けてください。

■ コマンドラインオプション
  -start T    この時刻より前をカット（08:05:00 / 08:05 / 2026-09-26 08:05:00）
  -end T      この時刻より後をカット
  -localdate  RMC の日付を現地日付（ヘッダのタイムゾーン）で出力
  -weeks N    補正週数を手動指定（0 で補正なし、既定は自動）
  -o DIR      出力先フォルダ
  -kml        KMZ ではなく KML で出力（凡例画像なし）
  -nokml      Google Earth 用ファイルを出力しない（NMEA のみ）
  -nopause    時刻の問い合わせと終了時の Enter 待ちをしない
