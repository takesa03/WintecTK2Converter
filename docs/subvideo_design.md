# サブ動画の重ね表示と表示のレイアウトエディタ 設計メモ

2026-11-19 作成。まだ実装していない（計画の段階）。10 章の決めごとは同日にユーザーが確認。

走行動画（メイン）に、別のカメラの動画（サブ。例: ペダルを撮った動画）を縮小・トリミングして重ねる。
あわせて、動画に重ねる表示（速度計・G メーター・地図・ラップタイムなど）の ON/OFF と位置を画面で直せる簡易エディタを作る。
時刻合わせ画面の再生・切り出し（表示を焼き込む）・動画で比較・動画素材の書き出しのすべてが、同じレイアウトで表示・出力する。

## 2. 時刻の持ち方

サブ動画も **ログの時刻に対して t0 を持つ 1 本の動画** として扱う（メインからの差では持たない）。

- `ログ名.log.json` の `videos` に、今の Entry と同じ形で入れ、`role = "sub"` を足す（今の動画は role なし = メイン）
- 合わせる操作はメインからの差（「サブの x 秒 = メインの y 秒」）で行い、保存するときに `サブの t0 = メインの t0 + (メインの秒 − サブの秒)` に直す
- こうしておくと、
  - 動画素材の書き出し（ログの時刻で動く）・動画で比較（周回の時刻で探す）でも、メインを経由せずにサブを探せる（`VideoStore.Find` と同じ考え方）
  - 「データをまとめる...」（`LibraryPacker`）は videos を全部コピーするので、サブも何もしなくてもいっしょに運ばれる
- `VideoStore.Find`（比較の画面でメインを探す）は role = sub を除く。サブを探す `FindSub(log, t0, t1)` を別に作る
- 1 本のメインに対してサブは 1 本（まずは）。同じ時間帯にサブが複数あれば、範囲を一番よく覆うものを使う

Entry に足す項目（案）:

| キー | 中身 |
|---|---|
| `role` | `"sub"`（無ければメイン） |
| `crop` | `[左, 上, 右, 下]`。元の動画の幅・高さに対する割合（0〜0.49）。解像度が違う写しに差し替えても使える |
| `syncNote` | どう合わせたか（`audio 62.2` / `manual` など。画面の案内用） |

**トリミングはサブ動画ごと（log.json）、表示する枠はレイアウト（ini）** に分ける。トリミングはカメラの付け方で決まり、枠の位置は見せ方の好みで決まるため（10 章で決定）。

## 3. レイアウト ini に足す項目（`[subvideo]`）

今の書き方（1920×1080 基準、anchor / x / y）にそろえる。

```ini
[subvideo]
show   = 1
anchor = bottomleft   ; 枠の基準の角
x      = 15
y      = 220
width  = 480          ; 表示する枠 (この中に縦横比を保って収める)
height = 270
align  = center       ; 枠より小さくなったときの寄せ方 (center / left / right / top / bottom)
border = 2            ; 枠線の太さ (0 で無し)
bordercolor = #80FFFFFF
opacity = 1.0
```

- 収め方: トリミング後の画像を、縦横比を変えずに枠に収まる最大の大きさに縮小（拡大もする）。余りは透明
- サブ動画が無い・範囲外の時刻は何も描かない（枠線も描かない）
- 重なり順: メインの映像 → サブ動画 → 今の表示（速度計など）。表示がサブの上に乗るので、地図などと重ねても数字が隠れない

## 4. 再生（時刻合わせ画面・動画で比較）

- `VideoPane` に 3 枚目の画像（メインと表示の間）を足し、`FrameReader` をもう 1 つ持つ
  - サブは小さめに読む（枠の大きさ × 画面の倍率。最大 960 幅程度）。トリミングは読んだ画像を WPF 側で切り取る（ffmpeg を読み直さずに調整を即反映できる）
  - 時刻: `サブの秒 = (メインの秒 + メインの t0) − サブの t0`。メインの時計（`PlayClock`）に従い、ずれたら Seek
- サブの音声は再生しない（読まない）
- 動画で比較は 1 画面ごとに自分のサブを探して出す（2 画面なら最大 4 本を読むので、サブは低い解像度で読む）

---

## 5. 時刻合わせ画面での操作

メインの時刻合わせの下に「サブ動画」の欄を足す。

- 「サブ動画を開く...」「外す」
- **音声で合わせる**: メインの今の位置の前後（既定 ±60 秒の窓、探す範囲 ±5 分）の音声と、サブの音声の包絡の相互相関。候補を 3 つまで、点数付きで出す（心拍の FIT 合わせと同じ見せ方）。全体が短ければ全体で合わせる
  - 読み込みは `FfVideo.ReadAudio`（今のエンジン回転の解析で使っている）を流用
  - 計算は 1 章の確認と同じ: 差分の絶対値 → 10ms ごとの平均 → log → 1 秒の移動平均を引く → FFT の相関
- **手動の調整**: ずれの数値欄（秒、0.001 まで）と、±1 フレーム（サブの fps）・±0.1 秒・±1 秒のボタン。再生しながら直せる
- 目安のため、メインとサブを同じ時刻で並べて止める「確認」表示（サブを一時的に大きく表示）があると合わせやすい
- 保存はメインの t0 と同じタイミング（「保存」で log.json に書く）

## 6. 表示のレイアウトエディタ（新しい画面 `LayoutEditorWindow`）

### 6.1 開く場所

- 動画素材の書き出し（`OverlayExportWindow`）のレイアウト欄の「参照...」「読み直す」の横に **「編集...」**
- 時刻合わせ画面・動画で比較にも「表示の編集...」（今見ている動画の上で直せるのがいちばん分かりやすい）
- 編集中は呼び出し元のプレビューにそのつど反映（保存前でも）。閉じるときに保存するかを聞く

### 6.2 画面

- 左: 要素の一覧（speedometer / gmeter / tacho / map / session / heart / laptime / sector / graph / info / subvideo）。チェックで ON/OFF
- 中央: 1920×1080 のプレビュー。背景は呼び出し元の今のフレーム（無ければ灰色）。選んだ要素に枠を出し、**ドラッグで移動**
- 右: 選んだ要素の項目（anchor・x・y・scale / size / width / height、色など主なもの）。数値欄は上下キー・ホイールで増減
- サブ動画を選んだときは、枠（位置・幅・高さ）に加えて **トリミングの上下左右**（スライダーと数値）。トリミングはサブ動画の元の絵の上に切り取り線を出して直す小窓も付ける

### 6.3 作りの要点

- ドラッグのために、`OverlayRenderer.Draw` が描いた要素の外枠を `Bounds`（要素名 → Rect）に残すようにする。当たり判定はこの枠で取る
- ドラッグの結果は anchor を保ったまま x / y に直す（右下基準なら右・下からの距離）
- `below = session`（laptime）・`above = sector`（graph）の付いた要素を動かしたら、その指定を外して位置を数値にする（確認の文を出す）。`[heart]` は session に付いて動く
- `graph` の ON/OFF は今どおり画面のチェック（`OverlayPrefs.Graph`）と共通にする（ini の show ではなく）
- **保存は ini の書き換え**: 行の並び・コメント（`;` と行頭の `#`）・知らないキーをそのまま残し、変えた値だけを書き換える（無いキーは節の最後に足す）。`OverlayLayout` に書き込み（`Set(section, key, value)` と `Save()`）を足す
- `overlay_default.ini`（exe の横、発行で上書きされる）は直接書き換えない。初めて保存するときは「名前を付けて保存」で別のファイル（既定 `overlay_user.ini`、exe の横）にし、`Settings` の `Overlay.Layout` をそれに切り替える
- 元に戻す（Ctrl+Z）は 1 段階ずつ、操作の履歴で持つ（最低限）

## 7. 出力

### 7.1 切り出し（表示を焼き込む、`FfVideo.ExportClip`）

ffmpeg の入力を 3 つにする（0 = メイン、1 = サブ、2 = 表示のパイプ）。

```
-ss {メインの開始} -i main.mp4
-ss {サブの開始} -i sub.mp4            ; サブの開始 = メインの開始 + メインの t0 − サブの t0
-f rawvideo -pix_fmt bgra -s WxH -framerate fps -i pipe:0
-filter_complex
 [1:v]crop=iw*(1-l-r):ih*(1-t-b):iw*l:ih*t,scale=W:H:force_original_aspect_ratio=decrease,fps={メインの fps}[s];
 [0:v][s]overlay=X:Y:eof_action=pass[m];
 [m][2:v]overlay=0:0:format=auto:eof_action=pass,format=yuv420p[v]
-map [v] -map 0:a:0?   ; 音声はメインだけ
```

- サブの開始が負（サブがメインより後に録り始めた）なら、サブの `-ss` は付けずに `-itsoffset {遅れ}` で後ろへずらす（それまではサブを描かない）
- サブが途中で終わったら `eof_action=pass` で消える（最後の絵で止めない）
- 出力の大きさが 1920×1080 以外なら、枠の位置・大きさを比で直す（表示と同じ規則）
- 切り出した動画は今どおり `overlay = true` で登録（比較の画面では使わない）。サブを焼き込んだかどうかは label に残す

### 7.2 動画で比較

- 比較の画面は今のところ表示だけ（書き出し機能は無い）。表示はレイアウトに従ってサブも出す（4 章）
- 2 画面を 1 本の動画に並べて書き出す機能は作らない（10 章で決定）

### 7.3 動画素材の書き出し（透明の ProRes 4444 / PNG 連番）

- 「サブ動画も含める」のチェックを足す（既定は OFF。Resolve 側でサブを別に重ねる人もいるため）
- 含めるときは、書き出す範囲のログの時刻からサブを `FindSub` で探し、ffmpeg でサブを読みながら（`FrameReader` を順に進める）表示の画像の下に貼って送る。`OverlayFrameSource` の描画の前にサブのフレームを描く形

## 9. 気を付けること

- 再生の重さ: メイン（HEVC 1080p60）＋サブを同時に読む。比較の画面は 2＋2 本。サブは小さく読み、読み込みを別スレッドにする（今の `FrameReader` と同じ）。表示の画像は UI スレッドで描かない（11/15 に 2 画面で固まった件）
- fps の違い: サブ 30fps・メイン 59.94fps。再生は「今の時刻以前の最新のフレーム」を出すだけで良い。切り出しは `fps` フィルターでメインに合わせる
- 回転・縦撮り: スマホの縦動画は回転のメタデータがある。ffmpeg は既定で自動回転するので、`Probe` の幅・高さを回転後で扱うこと
- 長い録画の時計の進み: 7 分では差なし。長い（30 分以上）素材で合わないときは「2 か所で合わせて速さを補正」を後で足せるよう、保存の形に余地を残す（`rate` キーを将来足す）
- ini を手で編集しているユーザーの値（コメント・並び）を壊さない（6.3）

## 10. 決めたこと（2026-11-19、ユーザーが確認）

1. **トリミングの置き場所**: サブ動画ごと（log.json の Entry の `crop`）。レイアウト（ini）には枠の位置・大きさだけを持つ
2. **保存先のレイアウト**: エディタの保存は別ファイル（初回は名前を付けて保存、既定 `overlay_user.ini`）。`overlay_default.ini` は直接書き換えない
3. **動画で比較**: 表示だけ（再生にサブとレイアウトを反映）。2 画面を並べた動画の書き出しは作らない
4. **動画素材の書き出し（透明の素材）**: 「サブ動画も含める」のチェックで選ぶ。既定は OFF
5. **サブの本数**: まずは 1 本。必要になったら `[subvideo2]` の形で広げる
