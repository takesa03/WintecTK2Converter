| offset | 型 | 内容 |
|---|---|---|
| 0 | u16 | フラグ: 1=トラック開始, 2=トラック終了, 0=通常（他ビットはPOI等の可能性） |
| 2 | u32 | 日時(UTC)ビットパック: 秒 bit0-5 / 分 6-11 / 時 12-16 / 日 17-21 / 月 22-25 / 年-2000 26-31 |
| 6 | i32 | 緯度 ×1e-7 度（南は負） |
| 10 | i32 | 経度 ×1e-7 度（西は負） |
| 14 | i16 | 高度 [m] |

速度(ノット)・進行方向はファイルに無く、TimeMachineXが前後点から計算してNMEAに出力している。
全4411点で緯度・経度・高度がNMEA出力と一致することを確認済み。

## 日付ずれの原因
GPS週番号ロールオーバー（1024週 = 7168日）。2007-02-09 + 7168日 = 2026-09-25（UTC）。
→ 修正は「日付に 7168 日を加算」でよい（時刻はそのまま）。

## 注意: RMCの日付はUTC
開始時刻は UTC 2026-09-25 22:08:06 = JST 2026-09-26 07:08:06。
NMEA規格では GPRMC の日付はUTCなので正しくは 250926。
現状の _mod.nmea は 260926（JST日付）にしている。UTC 15:00 を跨ぐログでは日付の扱いに注意。

## TimeMachineX の NMEA 出力仕様（逆解析）
1点につき2行、CRLF改行:
- `$GPRMC,hhmmss,A,ddmm.mmmmmm,N,dddmm.mmmmmm,E,速度(kn,%.1f),方位(%.1f),ddmmyy,,,,*CS`
- `$GPGGA,hhmmss,ddmm.mmmmmm,N,dddmm.mmmmmm,E,1,,,高度(整数),M,,M,,*CS`
- 速度: 直前の点とのハバーサイン距離（地球半径 6378137 m）÷ 時間差、ノット、小数1桁四捨五入。先頭点は 0.0。
- 方位: 大圏初期方位を 0–360 に正規化して整数に切り捨て。先頭点は 0.0、直前と同一座標なら 360.0。
- 緯度経度の分は6桁。TimeMachineX は倍精度演算の切り捨てで末尾が1小さくなることがある（最大 1e-6 分 ≈ 2mm）。

## コース定義の作成 (gui/CourseBuilder.cs, CourseWindow)
- 入力: .tk2 (`Program.LoadTrack`) または .nmea (`$GPRMC` のみ)。NMEA の日付は最初の 1 点だけ使い、以降は時刻の巻き戻りで日をまたぐ（`-localdate` 付きで出力した NMEA は日付と時刻の基準が異なるため）。複数ファイルはファイルの間を欠測扱いで連結。
- 方式: 局所平面 (m) に変換 → 走行区間に分割（欠測 2 秒超・速度 18km/h 未満で切る）→ 最長の区間で、出発点を区間内の約 60 か所に変えながら「出発点が後続の線分に 5m 以内・向き 30° 以内で戻る」までを 1 周の候補とし、いちばん短い候補を初期ループにする（1 秒間隔は点が最大 10m ずれるため、点どうしの距離では判定しない。出発点が区間の先頭だけだと、ピットレーンやラインから外れた位置のとき近くに戻るのが何周も先になり、複数周を 1 周としてしまう。2026-11-11 に鈴鹿の 5Hz ログで 28km になった件の対策）→ 2m 間隔に再標本化。立体交差（鈴鹿）は向きの条件で区別できる。
- 反復: 各点を参照ラインに投影（距離 25m 超・進行方向 60° 超は除外）→ 弧長 4m 幅のビンごとにオフセットの中央値 → 隣接ビンで平滑化して法線方向へ移動 → 平滑化・再標本化（40 回）。線分ではなく点を使うので、1 秒間隔でもカーブの内側に切り込まない。
- 周回の選別: 参照ラインの弧位置 (0-1) が 0.7→0.3 に巻き戻るごとに周回を数える。所要時間が中央値の 1.2 倍超・欠測あり・15km/h 未満まで落ちた周回（ピットイン・スピン等）を除き、残りでもう一度反復（25 回）。低速・ピット付近は測位のばらつきが大きいため。
- 実データ（レインボースポーツ, 2026-11-07, 1 秒間隔 4325 点）: 71 周中 44 周を採用、周長 約 648m、ばらつき 標準偏差 約 2.8m / P10-P90 幅 約 6m。軌跡は 150m 四方に収まる。フィルタなしだと標準偏差 3.4m・蛇行あり。
- コントロールライン: 既定は停止・低速（3km/h 未満）の点が集まる弧位置（ピット/スタート付近）。セクターは周長の (N+1) 等分。ゲートは中心線に直交し、片側 12m（GPS のばらつき分を見込む）。
- コース定義ファイル (`*.course.json`, `format=WintecTK2Course`): name, lengthM, clockwise, gateHalfWidthM, stats, gates[{name, distanceM, a, b}], centerline[{lat, lon}]（閉ループ, 約 2m 間隔）, sources。
- 注意: GPS の系統的なずれ（数 m の一律なオフセット）は平均化では消えない。ラップ計測ではログも同じずれを持つので影響しないが、Google Earth の衛星写真との重なりには出る。
- 起動: `WintecTK2Converter.exe -course ファイル...` でコース定義の作成画面を開く。
## ラップ・セクタータイム (gui/LapAnalyzer.cs, LapWindow)
- 入力: コース定義 (gates) と走行ログ。ゲートはコントロールから進行方向 (距離順) に並べる。区間 S1 = コントロール→Sector1, ..., 最後 = 最後のセクター→コントロール。
- 通過判定: 隣り合う点 (欠測 3 秒以内・速度 8km/h 以上) の線分とゲートの交点。進行方向と逆の通過は除外。同じゲートは 8 秒以内の再検出を除外。交点の位置比で通過時刻を線形補間 (1 秒間隔なので 0.1〜0.2 秒の誤差を見込む)。
- 停止の検出: 区間の平均速度が 6km/h 未満の連続 (ロガーが停止中に記録しない間の欠測も同じ位置なので停止になる) が 30 秒以上 (画面の既定。コード上の既定は 60 秒)。実データ (レインボースポーツ) では、止まる位置はコース上 s=612〜636m に集中し、ロガーは停止中ほぼ記録しない。
- セッション: 2 つの通過の間に停止があれば区切る。停止がなくても、コントロール通過後に次のラインをなかなか通らなければ区切る（ピットレーン走行中など）。待つ時間は「停止とみなす秒数」と「コントロール→次のラインの所要時間の中央値の 2 倍」の大きいほう（鈴鹿のように 1 区間が 40 秒を超えるコースで、毎周区切られないように）。コントロール通過後の停止 → 直前の周回を IN。コントロール到着前の停止 → その周回を「未完」の IN (通過済みの区間タイムは残す)。区切り後の最初の周回は OUT (停止からの発進、または Sector1 など途中のラインから計測)。通過が 1 回だけの空のセッションは捨てる。
- 無効・救済: セクターラインだけの検出漏れ → その区間は空欄、周回は有効。コントロールの検出漏れ・逆走 → 周回を無効 (×) にして次のラインから計測し直す (PARTIAL)。停止がないのに 120 秒以上途切れたら欠測として無効。
- 遅い周回: セッション内の周回タイム中央値の 1.25 倍超、またはどれかの区間がセッション内のその区間の中央値の 1.5 倍超 (スピンは特定の区間だけが大きく遅くなるため、区間の判定が効く)。備考に理由を出す。IN ラップは最後の区間が遅くなるのでこの判定で外れやすい。
- ベスト: Type=Normal・有効・遅い周回でない周回だけが対象。全体と、セッションごと。
- マーキング: ラップ・各区間は上記のベスト対象から、全体 (★, CSV は *) とセッション内 (※, CSV は s) を付ける。最高速は有効な Normal の周回 (遅い周回・IN も含む) の最高速度 (km/h) で、同じく全体とセッション内。CSV の BestSectors 列は S2* (全体) / S3s (セッション内) の並び、BestMaxKmh 列は * / s。
- コントロールラインの自動位置 (CourseBuilder): 停止点 (3km/h 未満) の位置の 5 パーセンタイルの 8m 手前。ピットインを「コントロール通過後の停止」にするため、停止位置より手前に置く。
- 実データの結果 (2026-11-07, レインボースポーツ): 6 セッション 65 周, ベスト 38.995 秒 (全体)。
- セッションの手動編集 (gui/SessionEdits.cs): ログごとに `ログ名.sessions.json` (`format=WintecTK2SessionEdits`, `splits`[時刻], `merges`[時刻]。時刻はログの通算秒で、ライン通過の時刻 = 周回の開始時刻)。`LapParams.Edits` で解析に渡す。分割 = その通過から新しいセッションにする (停止ではないので新しいセッションの最初の周回を OUT 扱いにしない)。通過がコントロールラインのときは、その通過で前の周回を最後まで計測してから分け (最後の周回は IN)、新しいセッションの周回はそのコントロールラインから始める。それ以外のラインで分けると、前の周回は「未完」、新しいセッションはそのラインから OUT として始まる。結合 = 自動 (停止判定) の分割を取りやめる (停止はなかったものとして、前のライン通過から計測を続ける。停止の時間はその区間・周回に入るので、その周回には `ContainsStop` と注記を付けてベスト対象外にし、欠測 (MaxSectorSec) の判定もしない)。結合の時刻はセッションの最初の通過時刻と一致させる。手動で分けたところを「結合」すると分割を取り消し、結合したところを「分割」すると結合を外す。時刻は設定を変えても動かないので、編集は保たれる。個人のログに紐づくので .gitignore 対象 (`*.sessions.json`)。
- ドライバー名の保存 (gui/DriverStore.cs): ログごとに `ログ名.drivers.json` (`format=WintecTK2Drivers`, entries[{startT, endT, driver}]。時刻はログの通算秒)。ログのそばに書けなければ `%LOCALAPPDATA%\WintecTK2Converter\drivers\`。復元は時間範囲の重なりが最大のエントリを採用するので、セッションの分かれ方が変わっても引き継げる。名前を編集して確定したときに保存し、解析直後に復元する。名前がひとつもなければファイルを削除する。個人のログに紐づくので .gitignore 対象 (`*.drivers.json`)。
- 比較再生 (gui/ReplayWindow.xaml(.cs)): 周回表で選んだ Normal・有効な周回を、`ReplayLap` (開始時刻 = コントロールライン通過を 0 秒として、GPS の点を Catmull-Rom 曲線で補間し、0.05 秒間隔の位置・走行距離に作り直したもの) にして、コース定義の中心線・ライン・走行位置の丸を Canvas に描く。差 = 周回の進み具合 (走行距離 / 周回の総距離) が同じになる時刻の、基準の周回との差 (＋ = 遅れ)。終点では総距離の違いに関係なく、ラップタイムの差と一致する。速度は位置の前後 0.3 秒の移動から求める。ログが必要なので CSV 表示中は使えない。
- CSV の読み込み (gui/LapCsv.cs): 保存した CSV を読み戻して `LapAnalysis` (読み取り専用の表示用) にする。開始時刻は秒まで (JST から通算秒に戻す)。ベストは * / s の印から復元する。保存→読み込み→保存で同一の CSV になることを確認済み。ログがないので分割・結合 (SessionEdits) は無効。
- CSV: Session, Driver, File, Lap, Type, Valid, StartTime (JST), 各区間 [s], LapSec, LapTime, 区間ごとの最高 km/h, MaxKmh, BestLap (* = 全体, s = セッション), Note。UTF-8 BOM。
## TimeMachineX の KMZ (GE_*.kmz) の構造（逆解析）
KMZ 内に KML 1 個。フォルダ: Track / Way_Point / Track_Point / Speed_Track(Km) / Km_Posts / Mile_Posts。
- Speed_Track(Km): 速度 [km/h] = floor(ハバーサイン距離 / 時間差 × 3.6)。20km/h 刻みの 7 帯
  （0-19 ffd355ba, 20-39 ffff0000, 40-59 ffffce87, 60-79 ff00ff7f, 80-99 ff00ffff, 100-119 ff007fff, 120- ff0000ff、KML の aabbggrr）。
  帯が変わる点で LineString を区切り、区間の終点 = 次区間の始点（線をつなぐため 1 点重複）。幅 5。
- Km_Posts: 累積距離（ハバーサイン, 6378137m）が 1km の倍数になる位置を前後 2 点の緯度経度で直線補間。名前 "N Km"。
- Mile_Posts も同様（1 mile ごと）。Track_Point は全点の Placemark（時刻・速度・方位・累積距離の説明付き）。

## KMZ/KML 出力（C# 版）
NMEA と同じ名前で `YYYYMMDD_HHMMSS.kmz` を出力（`-kml` で KML、`-nokml` で抑止）。KMZ = doc.kml + legend.png（凡例, System.Drawing で描画）。
- スタート / ゴール目印、走行軌跡 (gx:Track, 時間スライダー再生・線は透明・速度[km/h]を ExtendedData に格納)。
- Speed_Track(Km), Km_Posts は上記 TimeMachineX と同じ計算。検証: 参照実装で TimeMachineX の出力と比較し、
  Speed_Track 361 区間すべて色・点数が一致、Km_Posts 80 本の位置差は最大 0.18 m。
- 区間カット: 開始/終了の現地時刻を指定（ドロップ時に対話入力、または -start / -end）。
  カットは NMEA と KMZ の両方に適用し、距離・Km ポストはカット後のスタートから数える。
  入力の補助として、記録が 60 秒以上途切れた「停止区間」を一覧表示する。
- 座標は 1e-7 度の整数から10進度7桁を整数演算で作成。
- C# 版（ユーザー環境でビルド）の KMZ を参照実装と照合: Speed_Track 359 区間・Km_Posts 79 本とも一致（2026-09-26）。

## 高さの表示（altitude）
- Google Earth の地形（DEM）には橋・高架が無いため、clampToGround だと橋の上の走行が海面に描かれる。
- 既定 altitude=gps: 全要素（gx:Track, Speed_Track, Km_Posts, スタート/ゴール）を altitudeMode=absolute、
  高さ = GPS 高度の時間移動平均（altsmooth 秒, 既定 7）+ altoffset [m]。extrude=1 で地面まで幕。
- サンプルの GPS 高度: 名港中央大橋付近で 46→76→58 m と橋の形を捉えるが、平地の高架でも 40 m 台など全体に 10～20 m 高め
  （WBT-201 の垂直精度の限界）。altoffset で調整。
- altitude=ground で groundoffset > 0 のとき、全要素を altitudeMode=relativeToGround・高さ = groundoffset [m] にして地表から浮かせる（gx:Track・Speed_Track・Km_Posts・スタート/ゴール・ツアーのカメラ注視点）。GPS 高度は使わないので、橋の上でも地形（海面）からの高さのまま。
- 地形データ（国土地理院 DEM 等）と組み合わせた自動補正は未実装。

## 走行アニメーション（gx:Tour, tour=1 既定）
- tourstep 秒（既定 2）ごとに gx:FlyTo(smooth, duration = tourstep / tourspeed)。最初の 1 つは bounce 3 秒。
- 各 FlyTo の LookAt: 位置 = その時刻の車（前後の記録点から直線補間）、heading = 前後 5 秒の位置から求めた進行方向
  （5 m 未満の移動なら直前の向き。tourheading=north で 0 固定）、tilt = tourtilt、range = tourrange、
  gx:TimeSpan [スタート, その時刻] → 通過済みの要素だけ表示、gx:Track のアイコンがその時刻の位置に出る。
- Speed_Track はツアー時は記録点ごと（通常 1 秒）に区切り、各区間に TimeSpan begin = 区間終点の時刻 − tourlead 秒（既定 0: 車が通過した点まで描く。先端は最大 1 点ぶん車の後ろ。+1 にすると先端が車の前へ出る）。
  （2026-10-03: 以前は 3 点ごと・begin = 終点で最大約 2 秒遅れ → 記録点ごと・begin = 始点にしたら車より先行 → begin = 終点 + tourlead で調整可能に）
- tourseg = N (>1) のとき、記録点の間を N 等分した小区間ごとに Speed_Track を分け、各小区間の TimeSpan begin = その終点の時刻（小数秒 .fff 付き）− tourlead。線が 1/N 秒刻みで伸びる（記録点の間は直線補間, 色は元の区間と同じ）。小数秒の時刻を Google Earth が解釈できない場合は tourseg=1 に戻す。
- trackline=1（単色の線モード）: 走行軌跡 (gx:Track) 自身に LineStyle（trackcolor, trackwidth）を付けて表示する。Google Earth がタイムスパンに合わせて線を車の位置（補間済み）まで描くため滑らか。Speed_Track(Km) フォルダは visibility=0（非表示。チェックすれば静的な色分けとして表示可）で、ツアー用の分割・TimeSpan は付けない。ツアーのカメラ・Km ポスト・スタート/ゴールの時間表示は従来どおり。
- carname: gx:Track の Placemark 名 = マーカー（track.png）の下に出るラベル。LabelStyle の scale = carlabel。空なら名前は「走行軌跡 (時間再生)」でラベルは出さない（scale 0）。
- カメラの向き: 前後 tourheadwin 秒（既定 5）の位置から進行方向を求め、tourheadtau 秒（既定 0 = すぐ向く）の遅れで追従（kf = 1 − exp(−tourstep / tau)、角度は直前の向きから最短で回す）。heading は 360 をまたいでも連続した値（361 など）で出力し、北をまたぐときの一回転を防ぐ。
  Km ポストは通過時刻、スタート/ゴールはその時刻から表示。
- 動画化: Google Earth Pro「ツール → ムービーメーカー」でツアーを録画。
